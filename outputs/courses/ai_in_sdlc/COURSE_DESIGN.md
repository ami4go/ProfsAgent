**Credits:** 2 · **L-T-P:** 1.5-0-1 (credits = L + T + P/2) · **Weeks:** 13 (mid-semester exam after week 7) · **Level:** 4xx · **Department:** CSE · **Lectures:** 13 × 1.5 h · **Labs:** 6 × 2 h

## Description

How AI, above all large language models and coding agents, is used in every phase of the software development lifecycle: requirements, design, construction, code review, testing and debugging, security, delivery and maintenance. Students use the tools on a team project, learn what they do reliably and where they fail, verify their output with tests and reviews, and judge their effect and risks with published evidence and their own measurements.

**Central question:** How do you get reliable software out of tools that are fast, fluent and sometimes wrong?

**Students:** B.Tech 3rd/4th year; M.Tech (BTECH-CSE, BTECH-CSAI, MTECH-CSE); assumed background: CSE201 Advanced Programming; basic software engineering practice (Git, unit tests).

## Prerequisites and positioning

- **CSE201** (mandatory): relies on building multi-component programs, unit testing, version control and collaboration, object-oriented design. Students must be able to build, test and version a multi-module program before they can judge AI-written code.
- **Compared with CSE701:** CSE701 Topics in Software Engineering: AI in SE (4 credits, 7xx) is a research course on data and ML for software engineering: repository mining, defect prediction, project health and bug triage from papers. AI in SDLC is a 2-credit 4xx practice course: students use LLM assistants and agents in every lifecycle phase, verify their output and judge their effect and risks. Overlap is limited to the requirements, repair, testing and review topics, taught here hands-on with current tools.

## Labs

- **Week 2 · Prompting and context with a coding assistant.** Solve the same three tasks with inline completion, chat and an agent; vary the context given (files, conventions, tests) and log which failures each change removes. _Tools:_ Python, VS Code, an AI coding assistant (free tier). _Practises:_ CO1.LO2.
- **Week 4 · From interview to user stories and a decision record.** From a recorded stakeholder interview, use an assistant to draft user stories with Given-When-Then criteria, list and resolve ambiguities, then compare two architectures and write an ADR with a Mermaid diagram. _Tools:_ an LLM chat assistant, Markdown, Mermaid. _Practises:_ CO1.LO3, CO1.LO4.
- **Week 6 · Generate a feature, then review the pull request.** Implement a specified feature with an agent on a branch, open a pull request, and review a classmate's AI-generated PR against the course checklist; fix the critical findings. _Tools:_ Git, GitHub, an AI coding agent, pytest. _Practises:_ CO2.LO1, CO2.LO2.
- **Week 8 · Tests that catch bugs: coverage and mutation score.** Generate unit tests for a module with an assistant, measure branch coverage and mutation score, remove tests with wrong oracles, then localise and repair two seeded faults with AI help. _Tools:_ pytest, coverage.py, mutmut, an AI assistant. _Practises:_ CO2.LO3, CO2.LO4.
- **Week 10 · Secure the pipeline.** Audit an AI-written repository for insecure code, hallucinated or vulnerable dependencies and secrets; add static analysis and an AI review step to a GitHub Actions workflow. _Tools:_ GitHub Actions, Semgrep, pip-audit, gitleaks. _Practises:_ CO3.LO1, CO3.LO2.
- **Week 12 · Migrate and measure.** Migrate a legacy module to a newer library version with AI help, keep the regression tests green, and time comparable tasks with and without the assistant to report the measured effect. _Tools:_ an AI coding assistant, pytest, a time log. _Practises:_ CO3.LO2, CO3.LO3.

Infrastructure: a free-tier AI coding assistant or agent for every student; GitHub accounts with Actions enabled; Python 3.11+ with pytest.

**Team project (30%).** Teams of 3–4 build a small web product with AI assistants across the whole lifecycle, in three milestones: (1) requirements and design (user stories with acceptance criteria, an architecture decision record); (2) build and test (every AI-written change reviewed, tests with a mutation-score target); (3) ship, secure and measure (CI with an AI review step and static analysis, a security audit, timed measurements of AI's effect, and the team's reflection and AI-use policy).
