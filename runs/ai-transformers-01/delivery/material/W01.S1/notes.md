## Learning outcomes

- Describe how a recurrent network processes a sequence and why its fixed-size state limits long inputs using a worked encoder-decoder translation example, naming the vanishing-gradient and bottleneck problems (CO1.LO1)

## 3. What is sequence modelling?

- Sequences have variable length and order matters
- Examples: text, speech, time series
- Feed‑forward nets cannot handle variable length

**Notes** (7 min · outcomes CO1.LO1 · sources [C1]): Introduce the idea that many tasks involve sequences: text, speech, time series. Explain that a sequence model must capture order and variable length. Mention that students have seen feed‑forward nets but those cannot handle variable‑length input. This sets up why recurrent architectures were developed.

## 4. Recurrent neural network (RNN) basics

- Hidden state updated each time step
- Same weights reused across steps
- Output can be produced at every step

Input token → RNN cell → Hidden state → Output token

*RNN recurrence*

**Notes** (8 min · outcomes CO1.LO1 · sources [C1]): Describe the RNN recurrence: h_t = f(W_hh h_{t-1} + W_xh x_t). Emphasize weight sharing across time steps, which gives parameter efficiency but creates a deep computational graph when unrolled. Note that the hidden state is the only memory passed forward.

## 5. Encoder‑decoder translation with RNN

- Encoder reads source tokens sequentially
- Final hidden state becomes context vector
- Decoder generates target conditioned on context

Source tokens → Encoder RNN → Context vector → Decoder RNN → Target tokens

*Encoder‑decoder pipeline*

**Notes** (10 min · outcomes CO1.LO1 · sources [C2]): Walk through the classic encoder‑decoder architecture for machine translation. The encoder reads the source sentence token by token, updating its hidden state. After the last source token, the final hidden state becomes the context vector c. The decoder is another RNN initialized with c and generates the target sentence one token at a time.

## 6. Worked example: translating "I love you" (Worked problem)

- Encoder produces hidden states h1, h2, h3
- Context vector c equals final hidden state h3
- Decoder starts from c and emits "Je"
- Decoder continues with "t'aime"

Encode 'I love you' → Hidden states h1..h3 → Context vector c → Decode 'Je t'aime'

*Step‑by‑step translation*

**Notes** (10 min · outcomes CO1.LO1 · sources [C2]): Use a concrete short sentence pair to illustrate the flow. Show how the encoder produces hidden states h1, h2, h3 for 'I love you'. The context vector c = h3 is passed to the decoder, which then emits 'Je', 't', 'aime'. Point out that all source information must be compressed into c, which becomes a bottleneck for longer sentences.

## 7. Fixed‑size context vector is a bottleneck

- Context vector dimension does not grow with source length
- Long sentences force compression into same vector
- Information loss limits translation quality

**Notes** (7 min · outcomes CO1.LO1 · sources [C2]): Explain that the context vector has fixed dimensionality regardless of source length. As the source grows, the encoder must squeeze more information into the same vector, causing loss of detail. This is the information bottleneck that motivated attention.

## 8. Vanishing gradient problem in deep unrolled RNNs

- Gradients multiplied by same matrix many times
- Vanishing gradients erase long‑range signals
- Exploding gradients cause unstable training

| Problem | Effect |
|---|---|
| Vanishing gradient | Long‑term dependencies lost |
| Exploding gradient | Unstable training |
| Sequential computation | No parallelism |

*Core RNN training problems*

**Notes** (8 min · outcomes CO1.LO1 · sources [C4]): When the RNN is unrolled for many steps, gradients are multiplied by the same weight matrix repeatedly. If the spectral radius is <1, gradients vanish; if >1, they explode. Both make learning long‑range dependencies hard. The sequential nature also prevents parallel computation on GPUs.

## 9. LSTM and GRU mitigate but do not eliminate the issues

- Gating creates near‑constant gradient paths
- Still process tokens sequentially
- Final hidden state remains a single vector

**Notes** (6 min · outcomes CO1.LO1 · sources [C3]): LSTM and GRU introduce gating mechanisms that create paths with near‑constant gradient flow, alleviating vanishing gradients. However, they still process tokens sequentially and still compress the entire source into a final hidden state, so the bottleneck remains for very long sequences.

## 10. Training difficulty for very long sequences

- Memory for back‑propagation grows linearly
- Gradient paths stay long despite gating
- Difficulty varies with task and model size

**Notes** (6 min · outcomes CO1.LO1 · sources [C4]): Even with gated units, training on very long sequences is difficult: memory for back‑propagation through time grows linearly, gradient paths remain long, and optimization can stall. The severity depends on the specific task, model size, and training tricks such as gradient clipping.

## 11. Check: Identify the encoder‑decoder bottleneck (Check)


**What is the main limitation of the fixed‑size context vector in an RNN encoder‑decoder?**

A. It forces the decoder to generate tokens in parallel
B. It compresses the entire source sequence into a single vector
C. It eliminates the need for backpropagation through time
D. It allows unlimited sequence length

*Answer: B. It compresses the entire source sequence into a single vector. The context vector is a bottleneck because all source information must be compressed into one fixed‑size vector, limiting long sequences. The tempting wrong option about parallel generation is incorrect because RNN decoders generate sequentially, not in parallel.*

**Notes** (4 min · outcomes CO1.LO1): This question checks whether students understand that the fixed‑size context vector is the bottleneck. The correct answer highlights compression; the distractor about parallel generation is a common misconception because attention later enables parallelism.

## 12. Why attention helps: soft lookup instead of hard bottleneck

- Decoder query attends to all encoder states
- Attention weights produce a dynamic context
- No single vector must hold everything

Decoder query → Attention scores → Weighted encoder states → Context vector

*Attention mechanism*

**Notes** (8 min · outcomes CO1.LO1 · sources [C2]): Introduce attention as a soft lookup: at each decoder step, a query vector is compared to all encoder hidden states (keys) to produce attention weights. The weighted sum of values yields a context vector that changes per decoding step, removing the single‑vector bottleneck.

## 13. Information flow comparison: RNN vs Attention

- RNN path length grows with sequence length
- Attention gives constant‑length paths
- Attention enables parallel computation

| Model | Path length | Parallelism | Context flexibility |
|---|---|---|---|
| RNN encoder‑decoder | O(sequence length) | Sequential | Single fixed vector |
| Attention | O(1) per step | Parallel across heads | Dynamic per token |

*RNN encoder‑decoder vs Attention*

**Notes** (7 min · outcomes CO1.LO1 · sources [C2]): Compare the two architectures on three dimensions. RNN encoder‑decoder has a path length proportional to sequence length, strictly sequential decoding, and a single fixed context. Attention provides constant‑length paths, enables parallel computation across heads, and yields a dynamic context per target token.

## 14. Check: Attention advantage over RNN bottleneck (Check)


**How does attention address the bottleneck of the encoder‑decoder RNN?**

A. By using a larger fixed‑size vector
B. By allowing the decoder to attend to all encoder hidden states at each step
C. By removing the encoder entirely
D. By training the decoder without gradients

*Answer: B. By allowing the decoder to attend to all encoder hidden states at each step. Attention computes a weighted sum of all encoder hidden states, giving the decoder direct access to the whole source sequence. Option A is wrong because attention does not rely on a single fixed‑size vector.*

**Notes** (4 min · outcomes CO1.LO1): This question verifies that students grasp the key advantage of attention: direct access to all encoder states. The distractor about a larger fixed vector is plausible but incorrect because attention does not rely on a single vector.

## 15. Key takeaways (Summary)

- RNNs process sequences step by step with a hidden state
- Encoder‑decoder compresses source into one context vector
- Fixed‑size vector creates an information bottleneck
- Vanishing/exploding gradients hinder long‑range learning
- LSTM/GRU improve gradients but not the bottleneck
- Attention removes the bottleneck with dynamic soft lookup

**Notes** (5 min · outcomes CO1.LO1): Recap the main points: RNNs process sequences step by step with a hidden state; encoder‑decoder compresses the source into one vector; this creates an information bottleneck and vanishing‑gradient problems; LSTM/GRU help gradients but not the bottleneck; attention solves both by letting the decoder attend to all encoder states dynamically.
