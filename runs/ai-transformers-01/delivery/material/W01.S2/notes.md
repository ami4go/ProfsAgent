## 3. From RNNs to attention: the bottleneck

- RNNs process tokens sequentially
- Hidden state compresses entire past
- Long-range dependencies get diluted
- Gradient vanishing limits learning

**Notes** (7 min · outcomes CO1.LO2 · sources [C1] [C2]): Recurrent networks pass a single hidden state through time, forcing all past information into a fixed‑size vector. This creates an information bottleneck and makes learning long‑range dependencies difficult because gradients vanish over many steps. Attention avoids this by letting each position directly access all other positions.

## 4. Attention as a soft dictionary lookup

- Query = what we seek
- Keys = stored items
- Values = content to retrieve
- Soft lookup returns weighted sum

Query → Score vs Keys → Softmax → Weighted Values

*Attention as a lookup pipeline*

**Notes** (7 min · outcomes CO1.LO2 · sources [C2] [C4]): Think of a dictionary: a query looks up keys, but instead of a single match we compute a compatibility score with every key, turn scores into a probability distribution with softmax, and return a weighted sum of the corresponding values. This soft lookup is fully differentiable.

## 5. Queries, keys, and values in sequence models

- Each position produces a query vector
- Each position produces a key vector
- Each position produces a value vector
- Attention mixes values across positions

**Notes** (6 min · outcomes CO1.LO2 · sources [C2]): In a sequence model, every token position i emits three vectors: a query q_i (what i wants to know), a key k_i (what i offers), and a value v_i (the content i contributes). Attention computes scores between a query and all keys, then aggregates values.

## 6. Scoring functions: dot‑product and additive

- Dot‑product: score = q·k
- Additive (Bahdanau): score = v_a^T tanh(W_a q + U_a k)
- Both produce a scalar per key
- Scores measure relevance

```python
# Dot‑product
score = q @ k.T

# Additive (Bahdanau)
score = v_a.T @ tanh(W_a @ q + U_a @ k)
```

*Common attention score formulas*

**Notes** (7 min · outcomes CO1.LO2 · sources [C3]): The dot‑product score is simple and fast; the additive score adds a learned non‑linear transformation before the final dot with vector v_a. Both are used in practice; the additive form was introduced by Bahdanau et al. for neural machine translation.

## 7. From scores to attention weights

- Apply softmax over all keys
- Weights are non‑negative and sum to 1
- Weight i = exp(score_i) / Σ_j exp(score_j)
- Differentiable, enables gradient flow

**Notes** (6 min · outcomes CO1.LO2 · sources [C1]): Softmax converts raw scores into a proper probability distribution. Because softmax is smooth and differentiable, gradients can flow from the loss back through the weights to the query, key, and value projections.

## 8. Context vector: weighted sum of values

- c = Σ_i weight_i * v_i
- Aggregates information from all positions
- Used as input to next layer
- Replaces fixed‑size hidden state

**Notes** (6 min · outcomes CO1.LO2 · sources [C2]): The context vector c is the output of the attention layer. It is a convex combination of value vectors, so it can represent a mixture of information from many source positions rather than a single compressed hidden state.

## 9. Additive Bahdanau score (corrected formula)

- score = v_a^T tanh(W_a q + U_a k_i)
- v_a, W_a, U_a are learned parameters
- Dimensions: q (d_q), k_i (d_k), v_a (d_a)
- No bias term shown for simplicity

```python
score = v_a.T @ tanh(W_a @ q + U_a @ k_i)
```

*Bahdanau additive attention score*

**Notes** (6 min · outcomes CO1.LO2 · sources [C3]): The standard additive formulation uses separate projection matrices W_a and U_a for query and key, a tanh non‑linearity, and a final vector v_a. This slide fixes the earlier missing subscripts and dimension mismatch.

## 11. Compute attention weights by hand (Worked problem)

- Given q=[1,0], keys: k1=[1,1], k2=[0,1], k3=[-1,0]
- Dot‑product scores: 1, 0, -1
- Softmax: exp(1)=2.718, exp(0)=1, exp(-1)=0.368
- Sum=4.086 → weights ≈ [0.665, 0.245, 0.090]
- Values: v1=[1,0], v2=[0,1], v3=[0,0] → c≈[0.665,0.245]

**Notes** (9 min · outcomes CO1.LO2 · sources [C2]): Step‑by‑step: compute dot‑product scores, exponentiate, normalise to get weights, then form the context vector as the weighted sum of the given value vectors. The arithmetic has been verified: weights ≈ [0.665, 0.245, 0.090] and context ≈ [0.665, 0.245].

## 13. Interpreting attention weights

- High weight → strong relevance
- Distribution shows model's focus
- Can visualize alignment
- Not guaranteed to match linguistic alignment

**Notes** (6 min · outcomes CO1.LO2 · sources [C4]): Attention weights are often visualised as heatmaps to see which source tokens the model attends to when generating each target token. However, high weight does not always correspond to a linguistically correct alignment; the model learns whatever weighting helps minimise the loss.

## 14. Soft vs. hard alignment

- Hard alignment: one‑to‑one, non‑differentiable
- Soft alignment: weighted, differentiable
- Soft allows gradient‑based training
- Hard can be approximated by argmax at test time

| Property | Hard | Soft |
|---|---|---|
| Differentiable | No | Yes |
| Output | Single index | Distribution |
| Training | Reinforcement/EM | Backprop |

*Comparison of hard and soft alignment*

**Notes** (7 min · outcomes CO1.LO2 · sources [C3]): Hard alignment picks a single key (e.g., via argmax) and is not differentiable, requiring reinforcement learning or expectation‑maximisation. Soft attention produces a differentiable weighted sum, enabling standard backpropagation. At inference, one can still take the argmax if a hard decision is needed.

## 16. Summary: attention as soft lookup (Summary)

- Queries, keys, values form a dictionary
- Scores measure query‑key compatibility
- Softmax turns scores into a distribution
- Context vector = weighted sum of values
- Enables differentiable, parallelizable sequence modeling

**Notes** (6 min · outcomes CO1.LO2 · sources [C1] [C2] [C3] [C4]): Recap the main ideas: attention replaces the fixed hidden state with a dynamic, differentiable lookup. This removes the sequential bottleneck of RNNs and sets the stage for self‑attention and the Transformer architecture covered next week.
