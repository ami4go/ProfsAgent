## 3. Recap: Single-Head Scaled Dot-Product Attention

- Attention computes weighted sums of values based on similarity between query and key vectors.
- The scaling factor scaling by square root of d_k prevents vanishing gradients in softmax.
- A single attention head averages representations across the sequence into one unified subspace.
- Masking hides future tokens or padding positions by setting logits to negative infinity.

**Notes** (5 min · outcomes CO2.LO2 · sources [C1] [C2]): In our previous session, we established the mathematical foundation of scaled dot-product attention. Remember that queries and keys interact via matrix multiplication to produce raw alignment scores, which are scaled and normalized with softmax to produce attention weights. However, a single attention operation calculates only one set of attention weights per query token. This limits the model to attending to a single subspace of context at a time, averaging out potentially distinct relationship types across the sequence.

## 4. Motivation: Why Use Multiple Attention Heads?

- A single attention head can only attend to one relationship type per sequence position.
- Multi-head attention allows the model to jointly attend to information from different representation subspaces.
- Different heads specialize in syntactic relations, positional proximity, or semantic associations.
- Combining multiple heads yields richer context representations than increasing projection dimension in one head.

**Notes** (5 min · outcomes CO2.LO2 · sources [C1] [C2] [C4]): Why do we need multiple attention heads instead of one big head? Imagine analyzing a sentence: a single word might need to focus on its verb for syntactic agreement, while simultaneously attending to its relative pronoun for semantic co-reference. A single attention head would force these competing signals to average out into one attention pattern. By splitting our projection into multiple heads, each head can independently learn to track distinct linguistic structures.

## 5. Architecture Overview of Multi-Head Attention

- Queries, keys, and values are projected into h lower-dimensional subspaces using learned matrices.
- Scaled dot-product attention runs independently and in parallel across all h heads.
- Outputs from each head are concatenated along the feature dimension back to d_model.
- A final linear transformation merges the concatenated head outputs into the final representation.

Input Q, K, V Matrices → Linear Projections (W_Q, W_K, W_V) → Split into h Parallel Heads → Scaled Dot-Product Attention → Concatenate Head Outputs → Final Output Projection (W_O)

*Multi-Head Attention Computation Flow*

**Notes** (6 min · outcomes CO2.LO2 · sources [C2] [C3] [C4]): Here is the architectural overview of multi-head attention. We start with query, key, and value matrices. Instead of directly applying attention on the raw embeddings, we project them through learned linear transformations. The projected tensors are partitioned across h heads, where scaled dot-product attention runs in parallel. Finally, the attention outputs from all heads are concatenated and passed through a final linear projection layer W_O.

## 6. Linear Projections for Queries, Keys, and Values

- Input matrices undergo separate learned linear transformations before attention.
- Parameter matrices W_Q, W_K, W_V project inputs into key/value feature spaces.
- Projections enable learned task-specific transformations before performing attention operations.
- Splitting projection outputs across heads satisfies d_k = d_v = d_model / h.

**Notes** (6 min · outcomes CO2.LO2 · sources [C1] [C2] [C3]): Let us inspect the linear projection step in detail. Before any head splitting occurs, the input embeddings of dimension d_model are multiplied by weight matrices W_Q, W_K, and W_V. These linear projections allow the network to project token representations into specific spaces tailored for matching queries with keys and gathering values. Crucially, we set the per-head dimension d_k equal to d_model divided by the number of heads h.

## 7. Hyperparameters and Tensor Dimension Relationships

- Total model embedding dimension d_model is partitioned into h heads of size d_k.
- Setting d_k = d_model / h keeps total computational cost similar to single-head attention.
- Batch size B and sequence lengths L_q, L_k remain tracked across all transformations.
- Output dimension after projection matches original input embedding dimension d_model.

| Tensor Stage | Batch & Seq Dims | Feature Dimension | Tensor Shape |
|---|---|---|---|
| Input Matrices | B, L | d_model | (B, L, d_model) |
| Linear Projection | B, L | d_model | (B, L, d_model) |
| Split & Transposed | B, h, L | d_k | (B, h, L, d_k) |
| Concatenated Heads | B, L | h * d_k | (B, L, d_model) |

*Tensor Dimensions Across Multi-Head Attention Steps*

**Notes** (6 min · outcomes CO2.LO2 · sources [C2] [C3]): Understanding tensor dimensions is the single most important skill for implementing transformer modules without bugs. Notice how the total feature dimension d_model is conserved throughout. By choosing d_k = d_model / h, the total computational complexity across all h heads remains roughly identical to performing single-head attention with dimension d_model. This table highlights how batch size B, sequence length L, and head count h interact.

## 8. Tensor Reshaping and Transposing for Parallel Heads

- Linear output shape (B, L, d_model) is reshaped to (B, L, h, d_k).
- Permuting dimensions to (B, h, L, d_k) isolates head index into batch dimension.
- Using PyTorch view requires contiguous memory layout after transposition.
- Dynamic sequence sizing requires inferring sequence length with -1 during view.

**Notes** (6 min · outcomes CO2.LO2 · sources [C2] [C3]): To compute attention across all heads in parallel using standard matrix operations, we reshape our 3D tensor of shape (B, L, d_model) into a 4D tensor (B, L, h, d_k), and then transpose dimensions 1 and 2 to obtain shape (B, h, L, d_k). Placing the head dimension h adjacent to batch dimension B allows PyTorch batch matrix multiplication to automatically execute attention across both batch items and heads simultaneously.

## 9. Parallel Attention Matrix Multiplication across Heads

- Batch matrix multiplication broadcasts over batch size B and head dimension h.
- Query-key score matrix product has shape (B, h, L_q, L_k).
- Softmax operates along the last dimension L_k to generate attention weights per head.
- Multiplying by values yields head context tensor of shape (B, h, L_q, d_v).

**Notes** (6 min · outcomes CO2.LO2 · sources [C1] [C2] [C3]): Once queries and keys are reshaped to (B, h, L_q, d_k) and (B, h, L_k, d_k), PyTorch performs batched matrix multiplication over the last two dimensions. The resulting score tensor has 4 dimensions: (B, h, L_q, L_k). Softmax is computed along the final dimension L_k so that attention weights sum to 1 for each query token in every head independently. Multiplying by values produces context vectors of shape (B, h, L_q, d_v).

## 11. Concatenation and Output Linear Transformation

- Attention outputs from h heads with shape (B, h, L_q, d_v) are transposed back to (B, L_q, h, d_v).
- Contiguous reshaping merges head outputs into shape (B, L_q, d_model).
- Output linear layer W_O projects concatenated features back to model dimension.
- This final projection allows interaction between information gathered across different heads.

**Notes** (5 min · outcomes CO2.LO2 · sources [C1] [C2] [C3]): After context matrices are computed for each head, we must recombine them. We swap dimensions 1 and 2 back to obtain (B, L_q, h, d_v), invoke .contiguous(), and reshape into (B, L_q, d_model). Merging heads by simple concatenation is not enough: we must apply the final linear matrix W_O to allow representation signals from different heads to mix together effectively.

## 12. Worked Example: PyTorch Module Initialization (Worked problem)

- Define MultiHeadAttention inheriting from nn.Module.
- Verify divisibility: d_model must be divisible by num_heads.
- Instantiate projection layers W_Q, W_K, W_V, and W_O as nn.Linear.

```python
import torch
import torch.nn as nn

class MultiHeadAttention(nn.Module):
    def __init__(self, d_model, num_heads):
        super().__init__()
        assert d_model % num_heads == 0, "d_model must be divisible by num_heads"
        self.d_model = d_model
        self.num_heads = num_heads
        self.d_k = d_model // num_heads
        
        self.W_Q = nn.Linear(d_model, d_model)
        self.W_K = nn.Linear(d_model, d_model)
        self.W_V = nn.Linear(d_model, d_model)
        self.W_O = nn.Linear(d_model, d_model)
```

*PyTorch MultiHeadAttention Initialization*

**Notes** (7 min · outcomes CO2.LO2 · sources [C2] [C3]): Let us write the PyTorch module step by step. In __init__, we take d_model and num_heads as arguments. We assert that d_model is divisible by num_heads so that d_k is an exact integer. We create four nn.Linear layers: three for query, key, and value projections, and one for the final output transformation. Each layer maps from d_model to d_model.

## 13. Worked Example: Dynamic Reshaping and Forward Pass (Worked problem)

- Project inputs and reshape dynamically using -1 for sequence dimension.
- Compute scaled dot-product attention across batch and head dimensions.
- Transpose, concatenate heads, and apply the final projection layer.

```python
def forward(self, query, key, value, mask=None):
    B = query.size(0)
    Q = self.W_Q(query).view(B, -1, self.num_heads, self.d_k).transpose(1, 2)
    K = self.W_K(key).view(B, -1, self.num_heads, self.d_k).transpose(1, 2)
    V = self.W_V(value).view(B, -1, self.num_heads, self.d_k).transpose(1, 2)
    
    scores = torch.matmul(Q, K.transpose(-2, -1)) / (self.d_k ** 0.5)
    if mask is not None:
        scores = scores.masked_fill(mask == 0, -1e9)
    attn = torch.softmax(scores, dim=-1)
    context = torch.matmul(attn, V)
    
    context = context.transpose(1, 2).contiguous().view(B, -1, self.d_model)
    return self.W_O(context)
```

*PyTorch MultiHeadAttention Forward Pass with Dynamic Reshaping*

**Notes** (8 min · outcomes CO2.LO2 · sources [C2] [C3]): Pay close attention to how we reshape K and V using view(B, -1, self.num_heads, self.d_k). We use -1 for the sequence length dimension instead of passing the query sequence length L. This is critical because in encoder-decoder cross-attention, key and value sequence length L_k can differ from query sequence length L_q. Hardcoding L_q for K and V would cause a runtime crash whenever sequence lengths differ.

## 16. Computational Efficiency and Combined Projections

- Instead of 3 separate linear layers, Q, K, and V can be projected in a single merged matrix.
- Single projection matrix of size (d_model, 3 * d_model) reduces PyTorch kernel launch overhead.
- Result is split into Q, K, V along the last dimension prior to head reshaping.
- Modern frameworks like PyTorch nn.MultiheadAttention utilize fused implementations for speed.

**Notes** (5 min · outcomes CO2.LO2 · sources [C1] [C2] [C3]): In industrial implementations such as PyTorch's native nn.MultiheadAttention or FlashAttention, performance optimization is key. Rather than executing three separate linear layers for W_Q, W_K, and W_V, models often project inputs using a single combined linear layer of shape (d_model, 3 * d_model). The output is then chunked into three tensors. This reduces GPU kernel launch overhead and improves memory bandwidth utilization.

## 17. Summary: Multi-Head Attention Architecture (Summary)

- Multi-head attention projects features into h subspaces to capture diverse relationship types.
- Hyperparameter selection sets d_k = d_v = d_model / h to preserve computational budget.
- Dynamic tensor reshaping using -1 accommodates differing query and key/value sequence lengths.
- Concatenation followed by linear projection W_O integrates representation space across all heads.

**Notes** (5 min · outcomes CO2.LO2 · sources [C1] [C2] [C3]): To summarize today's lecture: multi-head attention expands the capacity of attention mechanisms by projecting queries, keys, and values into h parallel subspaces. By setting d_k = d_model / h, we keep computational costs manageable. Always ensure your PyTorch code dynamically reshapes tensors using -1 to support variable key/value sequence lengths in cross-attention.
