## 4. Model Context Protocol (MCP) Architecture

- MCP standardizes communication between host environments and language model agents.
- Hosts run MCP client interfaces connected to lightweight local or remote servers.
- Servers expose tools, resources, and prompt templates without hardcoding API endpoints.
- Separation of host and server promotes modular and secure tool extensions.

Client Host Environment → MCP Client Protocol Layer → JSON-RPC Transport → MCP Server Tool Execution

**Notes** (6 min · outcomes CO1.LO2 · sources [C1]): The Model Context Protocol (MCP) provides an open standard connecting agent hosts—such as IDEs or CLI tools—with capability providers known as MCP servers. Rather than hardcoding custom integrations inside the agent codebase, MCP decouples the LLM host from tool execution. An MCP server exposes specific tools, system resources, and contextual prompt templates. The client host discovers these capabilities at startup. This modularity allows developers to plug in custom linters, test runners, or database inspection tools cleanly without altering the underlying agent logic.

## 5. Communication via JSON-RPC 2.0 and Transports

- MCP exchanges messages using standard JSON-RPC 2.0 requests and responses.
- Local MCP servers communicate over standard input/output (stdio) channels.
- Remote MCP servers use Server-Sent Events (SSE) with HTTP POST messages.
- Tool discovery occurs dynamically via protocol handshakes rather than REST registries.

```json
{
  "jsonrpc": "2.0",
  "method": "tools/list",
  "params": {}
}
// Response from MCP Server:
{
  "jsonrpc": "2.0",
  "result": {
    "tools": [{
      "name": "run_linter",
      "description": "Executes static code analysis",
      "inputSchema": { "type": "object" }
    }]
  },
  "id": 1
}
```

**Notes** (6 min · outcomes CO1.LO2): It is vital to understand how MCP host-server communication works. MCP relies on the JSON-RPC 2.0 protocol over two primary transports: stdio for local subprocesses and SSE (Server-Sent Events) for remote network connections. Tool registration does not involve calling a central REST API endpoint or sending POST requests to a central registry service. Instead, when the client host starts, it initiates a bidirectional JSON-RPC handshake directly with configured local or remote MCP servers. The host sends a tools/list request, and the server returns JSON schemas describing available functions and expected parameters.

## 6. Context Engineering Strategies for Agents

- Dynamic context retrieval limits token overhead while preserving key signals.
- System prompts define agent roles, tool usage constraints, and output formats.
- Tool schema descriptions direct when and how the model invokes tools.
- Context pollution occurs when excessive unformatted tool output fills the prompt.

**Notes** (6 min · outcomes CO1.LO2 · sources [C1]): Context engineering balances precision and token consumption. Providing full source files for large codebases exhausts context windows quickly and introduces noise. Effective context engineering selectively feeds relevant snippets, static analysis diagnostics, and test results into the agent prompt window. Accurate tool schemas are critical: clear descriptions guide the model on when to trigger an execution. Furthermore, tool outputs must be truncated or formatted cleanly to prevent context pollution from obscure stack traces or verbose logs.

## 10. Zero-Warning Workspace Integration Guidelines

- Environment variables must match local path and compiler setups.
- Schema mismatches between host and server lead to silent execution drops.
- Static analyzer outputs must be formatted to prevent warnings in host logs.
- Pre-flight verification ensures tool availability before agent execution.

| Check Item | Common Cause | Resolution Strategy |
|---|---|---|
| Unresolved Tool | Mismatched server name | Verify key in mcpServers JSON |
| Schema Error | Missing required schema field | Validate against JSON Schema spec |
| Analyzer Warning | Deprecated ruleset flag | Update local tool config flags |
| Test Timeout | Interactive prompt in script | Pass non-interactive batch flags |

**Notes** (7 min · outcomes CO1.LO2): To achieve a seamless workspace integration, configuration hygiene is essential. Common issues include schema validation errors, missing environment variables, or tool execution timeouts. When an MCP server returns unhandled stdout noise, static analyzers or client hosts may flag configuration warnings. Developers should run pre-flight checks: verifying that tool execution commands execute headlessly without waiting for user input, validating JSON Schemas against standard specifications, and ensuring that all paths in the host config resolve cleanly on the development machine.
