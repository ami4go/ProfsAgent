## 6. Agent Loop Architecture: Perception, Action, Feedback

- The perception phase collects user instructions, project files, and current terminal outputs.
- The action phase predicts the next logical step, such as modifying code or invoking a tool.
- The feedback phase executes the action and captures stdout, stderr, or static analysis warnings.
- Iterative loops repeat this sequence until public unit tests pass with zero warnings.

Perceive Context → Plan & Generate Action → Execute Tool/Code → Capture Feedback → Update Context Memory

*Closed-loop agent execution cycle*

## 8. Building an Iterative Test-Generation Agent Loop (Worked problem)

- Define initial prompt outside the retry loop to accumulate failure history.
- Execute code and run unit tests on each iteration.
- Append failure logs and stack traces directly to context prompt across attempts.
- Terminate early when all public tests pass.

```python
def repair_code_loop(base_prompt, max_retries=3):
    context_prompt = base_prompt
    for attempt in range(max_retries):
        response = agent.generate(context_prompt)
        result = run_junit_tests(response.code)
        if result.passed:
            return response.code
        context_prompt += f"\nAttempt {attempt+1} Failed:\n{result.error_log}"
    raise RuntimeError("Failed to fix tests within retry limit")
```

*Iterative test-repair loop retaining context history across retries*

**Notes** (8 min · outcomes CO1.LO2 · sources [C2]): Let me highlight a common mistake in agent feedback loops. If you reassign the context prompt inside the loop on every turn, you discard the previous error context! Notice in this code: context_prompt is initialized outside the loop as base_prompt. When a test fails, we append the error log to context_prompt. This preserves failure history across retries so the model learns from prior attempts.

## 12. Transition to Model Context Protocols (MCP)

- Custom scripts calling tools directly lack standard interfaces across different IDEs and agents.
- Model Context Protocol (MCP) provides an open standard for connecting AI models to tools and data.
- MCP decouples client workspace agents from backend integrations and custom tool servers.
- Enables safe, standardized tool discovery, context fetching, and execution.

Agent Workspace Client → MCP Protocol Interface → Custom MCP Server → External Tools & Analyzer APIs

*Standardized MCP client-server architecture*

**Notes** (7 min · outcomes CO1.LO2 · sources [C1]): Hardcoding API calls for linters and test runners in custom scripts doesn't scale across different development tools. Model Context Protocol (MCP) standardizes how agents discover tools, inspect context, and execute actions regardless of the underlying editor or IDE.

## 13. Introduction to Model Context Protocol (MCP) Architecture

- Client-Server Architecture: Host applications act as clients; tools act as MCP servers.
- Resources: Expose read-only data like file logs and repo status to enrich agent context.
- Tools: Executable functions exposed to the agent with defined JSON input schemas.
- Prompts: Reusable prompt templates exposed by servers to guide user and agent workflows.

**Notes** (5 min · outcomes CO1.LO2 · sources [C1]): MCP uses JSON-RPC to establish client-server communication. The MCP server exposes tools and resources. The agent client queries the server to discover what tools exist, what arguments they expect, and how to format inputs.

## 15. Example: Implementing a Custom MCP Tool Server for Linter Integrations (Example)

- Expose a linter execution tool using the MCP server SDK.
- Define schema parameters for source directory and target warning threshold.
- Run linter CLI and parse output into structured JSON for agent context.
- Return zero-warning status flag alongside detailed diagnostic lists.

```python
@mcp.tool()
def run_linter(source_dir: str) -> dict:
    """Runs Checkstyle and returns diagnostic warnings."""
    result = subprocess.run(["checkstyle", "-c", "/rules.xml", source_dir],
                            capture_output=True, text=True)
    warnings = parse_checkstyle_output(result.stdout)
    return {
        "passed": len(warnings) == 0,
        "warning_count": len(warnings),
        "diagnostics": warnings
    }
```

*MCP server tool handler for running Checkstyle linter*

The client agent automatically discovers this function schema, invokes it during a repair loop, and gets back structured output with passed, warning_count, and diagnostics.
