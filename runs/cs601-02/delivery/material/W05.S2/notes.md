## 4. Functional vs Non-Functional Requirements

- Functional: specific behaviors, inputs, outputs
- Non-functional: performance, security, usability

## 13. Executable Specifications: Definition and Benefits

- Executable spec = formal, machine-readable description of behavior
- Can be run as tests before any implementation exists
- Supports continuous validation and living documentation

## 14. Worked Example: Executable Spec for Refund Processing (Worked problem)

- Define the public interface: process_refund(request_id, amount)
- Write a spec that asserts expected outcomes
- Provide a minimal implementation to make the spec pass

```python
def process_refund(request_id: str, amount: float) -> dict:
    """Stub implementation for demonstration."""
    return {"request_id": request_id, "status": "approved", "amount": amount}

# Executable specification (runnable as a test)
def test_process_refund_approval():
    result = process_refund("REQ-123", 99.50)
    assert result["request_id"] == "REQ-123"
    assert result["status"] == "approved"
    assert result["amount"] == 99.50

if __name__ == "__main__":
    test_process_refund_approval()
    print("Spec passed")
```

*Executable specification and stub implementation in Python*

**Notes** (10 min · outcomes CO2.LO2 · sources [C1]): Walk through the code line by line. Explain that the spec (test) is written first, then the stub makes it pass. In practice, the spec would be more detailed and the implementation generated or written to satisfy it. This demonstrates translating module requirements into executable specifications (LO2).
