## 3. What Is Iterative Loop Engineering in AI Development?

- Iterative loop engineering drives autonomous agent code creation through feedback loops.
- Agents generate code, execute tests, evaluate output, and refine solutions repeatedly.
- Tracking agent behavior requires inspecting execution logs across every iteration cycle.

Prompt Dispatch → Code Generation → Test Execution → Log Feedback & Refine

*Iterative agent execution loop*

**Notes** (6 min · outcomes CO3.LO1 · sources [C4] [C6]): Iterative development with AI agents shifts programming from single-shot prompt engineering to managing structured execution loops. In an iterative loop, the coding agent continuously generates source code, executes tests or static analysis tools, inspects the failure output, and modifies its approach. Understanding this loop requires software engineers to trace state updates and control flow through agent log artifacts, ensuring that iterations converge toward correct code rather than infinite repetition or divergent bugs.

## 4. The Structural Components of Agent Execution Loops

- Observation: Agent receives test logs, compiler errors, or tool outputs.
- Thought: Model reasons about the failure cause and selects an action.
- Action: Model issues tool calls such as file edits or test commands.
- Environment State: Execution environment updates state and returns new logs.

Observation → Reasoning → Action Execution → Environment State Update

*Four-phase agent loop interaction*

**Notes** (6 min · outcomes CO3.LO1 · sources [C6]): Coding agents operate using an action-observation loop commonly structured around reasoning frameworks like ReAct. Each iteration begins with an observation of the workspace state, followed by internal reasoning where the LLM plans its next edit or command. The agent then executes a tool call, modifying files or running test scripts. Observing how control flows across these four phases in execution logs allows developers to pinpoint exactly where an agent strays off course during complex tasks.

## 5. Log Artifacts as Execution History Records

- Logs capture timestamped records of prompts, model calls, and environmental responses.
- Structured logs format tool invocations, shell commands, and stdout/stderr streams.
- Unstructured trace files contain full raw context windows sent back and forth.
- Tracing logs enables post-mortem analysis of agent reasoning and failure trajectories.

**Notes** (6 min · outcomes CO3.LO1 · sources [C3] [C6]): Log artifacts produced during iterative agent tasks serve as the primary source of truth for software developers. Unlike standard application logs, agent logs contain interleaved streams of LLM prompts, model responses, system tool invocations, and workspace environmental feedback like compiler outputs. By systematically analyzing these log artifacts, developers can trace every decision point, verify whether feedback was interpreted correctly, and diagnose systemic failure patterns across long-running development loops.

## 6. Identifying Control-Flow Steps in Execution Tracing

- Prompt dispatch marks the start of a logical reasoning step.
- Tool invocation indicates a transition from reasoning to environment action.
- Shell execution records system-level tool results and exit codes.
- State evaluation determines whether to continue looping or terminate.

| Step Type | Log Indicator | Information Captured |
|---|---|---|
| Prompt Dispatch | system_prompt / user_input | Context window & instructions |
| Tool Invoc | call_tool / function_call | Arguments & file targets |
| Shell Output | stdout / stderr / exit_code | Test results & error traces |
| Evaluation | loop_status / terminate | Convergence state |

*Control-flow step classification in agent logs*

**Notes** (6 min · outcomes CO3.LO1 · sources [C2] [C6]): Tracing execution logs requires categorizing log events into distinct control-flow steps. A typical trace includes prompt dispatch steps, tool calls like file reading or patch application, shell execution steps with process status codes, and loop condition evaluations. Recognizing these steps within multi-megabyte log files allows engineers to construct a step-by-step state machine of the agent's behavior, showing how inputs led to actions and how test outcomes modified subsequent prompts.

## 8. Log Formatting and Schema Standards

- JSON-Lines and OpenTelemetry provide structured formats for agent trace events.
- Key fields include trace_id, span_id, timestamp, step_type, and payload.
- Tool execution payloads record input arguments, execution duration, and exit status.
- Standardized schemas allow automated log parsing and visual trace representation.

```json
{
  "timestamp": "2026-03-29T10:15:00Z",
  "trace_id": "tr-8842",
  "step": 2,
  "type": "tool_call",
  "tool": "patch_file",
  "args": {"path": "src/app.py", "diff": "@@ -10 +10 @@"},
  "result": {"status": "success", "exit_code": 0}
}
```

*Structured JSON-Lines event entry from an agent execution trace*

**Notes** (6 min · outcomes CO3.LO1 · sources [C5] [C6]): Standardized log schemas like OpenTelemetry or JSON lines structure agent trace data into parseable events. Each entry captures essential metadata such as trace identifiers, step counters, timestamped payloads, and execution status. Using structured schemas ensures that both human developers and automated trace analysis tools can quickly parse control-flow steps, isolate failed tool invocations, and measure iteration latency across complex software engineering tasks.

## 11. Complexity Backpressure and Failure Modes in Traces

- Complexity backpressure occurs when context accumulation degrades model reasoning.
- Repeated patch failures introduce noise and context window bloat in traces.
- Oscillating loops, premature termination, and hallucinated tool arguments appear in logs.
- Tracing logs exposes when context limits degrade patch quality.

**Notes** (6 min · outcomes CO3.LO1 · sources [C3]): As agent loops extend over many iterations, context windows accumulate historical failure logs, standard error outputs, and discarded diffs. Research shows this causes 'complexity backpressure,' where model reasoning degrades due to context saturation. In execution logs, backpressure manifests as repeated patch retries, hallucinated file paths, or premature agent termination. Tracing these indicators helps engineers determine when to reset agent state rather than letting the loop run continuously.

## 14. Log-Informed Loop Engineering and Query Tuning

- Traces reveal exact prompts and context states that triggered agent errors.
- Query tuning modifies prompt templates based on observed log failure points.
- Context pruning truncates historical tool outputs to alleviate backpressure.
- Model Context Protocol (MCP) enables standardized context injection in loops.

Trace Log Analysis → Identify Context Bloat → Tune MCP Prompt → Re-run Agent Loop

*Trace-driven loop tuning workflow*

**Notes** (7 min · outcomes CO3.LO1 · sources [C5]): Tracing logs is not just a diagnostic tool—it directly informs query tuning and loop refinement. By analyzing execution traces, engineers discover where prompts were ambiguous or where tool output flooded the context window. Using frameworks like the Model Context Protocol (MCP), developers can dynamically prune irrelevant history or adjust system prompts, ensuring subsequent iterations maintain lean context and precise instruction flow.

Agent Execution → Telemetry Collector → Real-Time Guardrail → Dashboard / Intervene

**Notes** (6 min · outcomes CO3.LO1 · sources [C4] [C6]): In modern software factories, log tracing is integrated directly into CI/CD pipelines and developer tooling.
