| Execution Trace | Tool calls, file edits, commands | Tool misuse, runtime errors |

## 8. Example: Finding a Logic Error in Prompt Logs (Example)

- Defect: off-by-one error in loop boundary condition
- Log shows agent reasoning: "loop from 0 to n inclusive"
- Code diff reveals `for i in range(n+1):` instead of `range(n)`
- Fix: change to `range(n)` and add test for boundary

```python
# Agent-generated code (buggy)
for i in range(n+1):
    process(item[i])

# Fixed code
for i in range(n):
    process(item[i])

# Added boundary test
def test_boundary():
    assert process(item[0]) == expected
    assert process(item[n-1]) == expected
```

*Off-by-one error and fix*

**Notes** (10 min · outcomes CO3.LO3 · sources [C3] [C6]): Walk through the log entries step by step. Show how the agent's natural language reasoning leads to the code error. This is a worked example of the analysis process.

## 9. Worked Problem: API Misuse in Generated Code (Worked problem)

- Defect: incorrect use of library function `json.load` vs `json.loads`
- Factory output: generated code reads string but uses `json.load(file)`
- Execution trace shows `AttributeError: 'str' object has no attribute 'read'`
- Fix: replace with `json.loads(string)` and add input validation

```python
# Generated code (buggy)
import json
data = json.load(json_string)  # expects file-like object

# Corrected code
data = json.loads(json_string)  # parses string directly

# Added validation
if not isinstance(json_string, str):
    raise TypeError("Expected JSON string")
```

*API misuse error and correction*

## 10. Check: Log Analysis Fundamentals (Check)


**Which log type would most directly reveal an agent's reasoning error leading to an off-by-one loop bug?**

A. Prompt/response log
B. Execution trace
C. Test result log
D. Artifact diff

*Answer: A. Prompt/response log. Prompt/response logs capture the agent's natural language reasoning, where the off-by-one logic was expressed. Execution traces show the resulting code execution, not the reasoning. Test logs only show failure, not cause. Artifact diffs show code changes but not the reasoning.*

**Notes** (5 min · outcomes CO3.LO3): This checks understanding of log types. The most tempting wrong answer is execution trace because it shows the bug manifestation.

## 12. Check: Defect Identification Strategy (Check)


**When analyzing a software factory output, you see a test failure due to a missing authentication check. Which log should you examine first to find the root cause?**

A. Prompt log from the code generation stage
B. Execution trace of the test run
C. Deployment script log
D. Specification document

*Answer: A. Prompt log from the code generation stage. The prompt log from code generation shows whether the agent considered security requirements. The execution trace only shows the test failure. Deployment logs are too late. The specification may not reflect what the agent actually did.*

## 13. Common Failure Causes in Iterative Loop Engineering

- Reasoning errors: flawed logic in agent's natural language
- Tool misuse: incorrect API calls, wrong parameters
- Context loss: agent forgets earlier constraints
- Complexity backpressure: agent degrades on large tasks (C3)

| Reasoning Error | Prompt log shows flawed logic | Off-by-one, incorrect algorithm |
|---|---|---|
| Tool Misuse | Execution trace shows wrong API | json.load vs json.loads |
| Context Loss | Prompt log misses earlier constraint | Security requirement dropped |
| Complexity Backpressure | Later iterations show degradation | Incomplete code, hallucinations |

*Failure causes and corresponding log evidence*

## 14. Best Practices for Analyzing Iterative Logs

- Start from test failures and trace backward
- Correlate prompt logs with code diffs
- Use execution traces to verify tool usage
- Document findings with log references

Test Failure → Execution Trace → Code Diff → Prompt Log → Root Cause
