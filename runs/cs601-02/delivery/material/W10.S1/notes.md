## 4. Iterative development loop overview

- Plan → Code → Test → Validate
- Agents repeat loop until criteria met
- Each iteration produces a new trace
- Feedback drives next planning step

Plan → Code → Test → Validate → Decide

*Core iterative loop*

**Notes** (5 min · outcomes CO3.LO2 · sources [C1]): Explain that the loop is driven by autonomous agents; each pass generates a trace that can be analyzed for regressions or new failures.

## 5. Testing role in each iteration

- Unit tests verify new code
- Integration tests check component wiring
- Regression tests guard prior behavior
- Agents can synthesize tests automatically

**Notes** (5 min · outcomes CO3.LO2 · sources [C1]): Testing is not a one‑off phase; it runs every iteration. Agents may generate tests from specifications or from observed behavior.

## 6. Test types generated by agents

- Property‑based tests for invariants
- Mutation tests to assess suite quality
- Contract tests for API compliance
- Stress tests for performance limits

| Test type | Goal | Agent support |
|---|---|---|
| Property‑based | Invariant checking | High |
| Mutation | Suite effectiveness | Medium |
| Contract | API conformance | High |
| Stress | Performance bounds | Low |

**Notes** (5 min · outcomes CO3.LO2 · sources [C1]): Agents can produce diverse test families. Property‑based and contract tests enjoy strong tooling support; mutation and stress tests are harder to automate fully.

## 7. Validation strategies

- Static analysis before execution
- Dynamic checks during runs
- Runtime monitors for anomalies
- Cross‑iteration result comparison

**Notes** (5 min · outcomes CO3.LO2 · sources [C1]): Validation layers complement tests: static analysis catches syntax/type errors, dynamic checks assert contracts, runtime monitors flag unexpected states, and cross‑iteration comparison reveals regressions.

## 8. Trace analysis workflow

- Collect raw agent logs
- Parse into structured events
- Filter error‑related entries
- Cluster similar failure patterns
- Summarize root causes

Collect logs → Parse events → Filter errors → Cluster patterns → Summarize causes

*Five‑step trace analysis pipeline*

**Notes** (6 min · outcomes CO3.LO2 · sources [C1]): Walk through each step: collection from the factory, parsing with a schema, filtering for error codes, clustering using similarity metrics, and finally producing a concise failure report.

## 9. Common failure categories in agent logs

- Specification mismatch
- Environment configuration drift
- Dependency version conflict
- Resource exhaustion
- Logical error in generated code

**Notes** (5 min · outcomes CO3.LO2 · sources [C1]): These five categories cover most observed failures. Emphasize that a single log may contain multiple categories; the analysis goal is to separate them with evidence.

## 12. Check: Failure category matching (Check)


**Which log line most clearly indicates a specification mismatch?**

A. ERROR SpecParser: missing required field 'timeout'
B. WARN ConfigLoader: env VAR_API_KEY not set
C. ERROR DependencyResolver: version conflict libfoo 1.2 vs 2.0
D. ERROR MemoryMonitor: process exceeded 2GB limit

*Answer: A. ERROR SpecParser: missing required field 'timeout'. The SpecParser error shows the agent cannot understand the specification, a classic specification mismatch. The config warning is environment drift, the dependency error is a version conflict, and the memory error is resource exhaustion.*

**Notes** (5 min · outcomes CO3.LO2): Quick poll to verify students can map log patterns to failure categories.

## 13. Check: Trace analysis step order (Check)


**What is the correct order of the trace analysis workflow steps?**

A. Collect logs → Parse events → Filter errors → Cluster patterns → Summarize causes
B. Parse events → Collect logs → Filter errors → Summarize causes → Cluster patterns
C. Filter errors → Collect logs → Parse events → Cluster patterns → Summarize causes
D. Collect logs → Filter errors → Parse events → Summarize causes → Cluster patterns

*Answer: A. Collect logs → Parse events → Filter errors → Cluster patterns → Summarize causes. The workflow starts with collection, then parsing, filtering, clustering, and finally summarizing. Other orders break dependencies between steps.*

**Notes** (5 min · outcomes CO3.LO2): Reinforces the sequential nature of the analysis pipeline.

## 14. Best practices for iterative testing & validation

- Automate test generation each loop
- Version‑control trace artifacts
- Set clear pass/fail thresholds
- Review failure reports before next iteration

**Notes** (4 min · outcomes CO3.LO2 · sources [C1]): Stress that automation reduces human latency, versioned traces enable regression comparison, thresholds prevent flaky decisions, and regular review closes the feedback loop.
