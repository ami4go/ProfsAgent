## 3. Reliability Requirements for AI-Native Pipelines

- Correctness: outputs match specification
- Robustness: graceful handling of unexpected inputs
- Performance: latency and throughput bounds
- Reproducibility: deterministic results across runs
- Maintainability: clear contracts and low coupling
- Security: protection against injection and leakage

Emphasize that these requirements are not independent; a design decision often trades off one against another. ## 4. Automated Testing Pipeline Stages

- Specification capture (requirements, contracts)
- Code generation (LLM or agent)
- Static analysis (lint, type check, security scan)
- Dynamic testing (unit, integration, contract, property‑based)
- Stress & mutation testing for robustness
- Evaluation & selection (metrics, thresholds)

Spec → Generate → Static Analysis → Dynamic Tests → Stress/Mutation → Evaluate

*Typical AI‑native pipeline flow*

## 5. Specification‑Driven Development for AI Code Generation

- Formal specs (pre/post conditions, invariants) guide generation
- Specs become executable contracts for testing
- Reduces ambiguity between human intent and model output
- Enables automated verification of generated code
- Supports traceability from requirement to test

## 7. Complexity Backpressure as a Policy for AI Agents

## 9. Contract Testing for Service Interfaces

- Verifies provider/consumer compatibility
- Runs against a shared contract (OpenAPI, gRPC proto)
- Detects breaking changes early in CI
- Primary reliability target: correctness of integration
- Secondary benefit: maintainability through explicit contracts

**Notes** (5 min · outcomes CO4.LO2 · sources [C4]): Explain contract testing as a specialized integration test that validates interface compliance. It directly supports correctness by catching mismatched schemas, and indirectly aids maintainability by making contracts first‑class artifacts (C4).

## 10. Model Context Protocol (MCP) for Context Exchange

- MCP standardizes tool, resource, and context exposure
- Clients request context; servers provide typed resources
- Does not itself adjust context windows or perform retrieval
- Context selection and token‑budget policies are client‑side
- Improves traceability when versions and execution settings are controlled

**Notes** (5 min · outcomes CO4.LO2 · sources [C5]): Clarify that MCP is a protocol for exchanging context and invoking tools, not a built‑in context‑tuning mechanism. The 2026 query‑tuning framework (C5) uses MCP to standardize the context supplied to an agent; reproducibility gains come from the client controlling retrieval, versioning, and execution parameters.

## 12. Check: Reliability Requirement Identification (Check)


**Which reliability requirement is primarily addressed by static analysis gates (lint, type checking, security scans) in an AI‑native pipeline?**

A. Correctness
B. Robustness
C. Performance
D. Reproducibility

*Answer: A. Correctness. Static analysis detects defects and violations before execution, directly supporting correctness. While it can also catch some robustness issues, its primary purpose is to ensure the generated code conforms to language rules and specified contracts, i.e., correctness.*

## 15. Flakiness Mitigation in AI‑Generated Tests

- Quarantine flaky tests and rerun with fixed seeds
- Use deterministic test data and mock external services
- Apply statistical thresholds (e.g., 95% pass rate over 10 runs)
- Log environment hashes for reproducibility
- Integrate flakiness dashboard into CI

**Notes** (5 min · outcomes CO4.LO2 · sources [C6]): Summarize practical strategies from the autonomous coding agents study (C6) to reduce nondeterministic test failures. ## 16. Ensuring Reproducibility via Controlled Reruns

- Pin model versions, prompts, and temperature settings
- Version control all generated artifacts and test inputs
- Use containerized execution environments
- Record full provenance (context, seed, dependencies)
- Enable on‑demand replay for audit and debugging
