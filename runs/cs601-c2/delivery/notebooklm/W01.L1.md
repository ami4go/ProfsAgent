## 2 · Course context (paste as a text source)

```text
COURSE: Software Development using AI (IIIT-Delhi, level 3xx, 3/4-year B.Tech students)
LECTURE: W01.L1 · week 1 · Developer workflows and AI-assisted coding (120 minutes)

LEARNING OUTCOMES (what students must be able to do):
- Identify the core components of developer workflows and AI-assisted coding using contextualisation guidelines for most short items.

THIS LECTURE, PART BY PART:
1. Evolution from Traditional to AI-Augmented Developer Workflows (15 min, concept)
   Teaches: Understand how software development lifecycles transition from manual writing and manual searching to AI-augmented authoring. Identify the shift from linear edit-compile-debug loops to continuous speculative drafting and prompt refinement. Explain the fundamental expectations and boundaries of integrating language models into active development environments.
   Key terms: developer workflow, speculative drafting, edit-compile-debug, AI-assisted coding, augmented IDE
2. Core Architectural Components of Modern AI Code Assistants (15 min, mechanism)
   Teaches: Identify the primary software building blocks connecting an editor to an underlying generative model. Detail how client-side plugins gather telemetry, local buffers, and cursor positions before transmitting them through an orchestrator to an inference engine. Recognize the responsibilities of the local extension versus remote inference endpoints.
   Key terms: IDE extension, inference client, orchestrator, telemetry, local buffer
3. Context Retrieval and Window Slicing in AI Assistants (20 min, mechanism)
   Teaches: Understand how AI assistants extract active file snippets, open tabs, and recent terminal outputs to populate an inference prompt. Examine how context budgets limit input tokens and how sliding windows prioritize lines surrounding the current cursor position. Describe the trade-offs between local context breadth and token latency during autocomplete generation.
   Key terms: context window, prompt construction, cursor proximity, token budget, sliding window
4. Contextualisation Guidelines for Scoped Code Generation Tasks (15 min, concept)
   Teaches: Identify and apply core contextualisation guidelines to constrain AI prompts for short coding items such as utility functions, docstrings, and unit tests. Explain why providing explicit type signatures, interfaces, and minimal reproducible input-output examples produces deterministic code. Distinguish between over-contextualised prompts that exhaust token limits and under-contextualised prompts that cause generic completions.
   Key terms: contextualisation guidelines, scoped prompt, type signatures, short items, few-shot examples
5. Interaction Modalities: Ghost Text, Chat, and Inline Edits (15 min, comparison)
   Teaches: Compare the operational patterns of in-line ghost-text autocompletion, docked conversational sidebars, and targeted in-line refactoring. Analyze when a developer should rely on passive inline completion versus active conversational elicitation for complex logic. Identify the cognitive load and interruption costs associated with each interaction modality.
   Key terms: ghost text, inline completion, docked chat, inline refactoring, interaction modality
6. Demonstration of Context Feeding in an AI-Assisted IDE (15 min, demo)
   Teaches: Observe how an AI coding assistant dynamically alters suggested code based on open editor tabs, language server protocol (LSP) diagnostics, and active comments. Follow the step-by-step transformation of a prompt payload when new files are opened or relevant interfaces are imported. Recognize how real-time IDE state changes directly manipulate model generation outcomes.
   Key terms: LSP integration, ambient context, prompt payload, code completion demo, editor state
7. Common Failure Modes: Hallucination and Stale Context in Workflows (10 min, case study)
   Teaches: Examine concrete examples where AI assistants hallucinate deprecated API methods, fabricate package dependencies, or carry stale context across branch switches. Analyze how incomplete context retrieval leads to syntactically valid yet logically flawed code snippets. Identify the risks of silent degradation in code quality when developers accept completions without manual inspection.
   Key terms: hallucination, stale context, API hallucination, silent degradation, context poisoning
8. Verification Strategies and Quality Gates for AI-Assisted Code (15 min, discussion)
   Teaches: Evaluate verification techniques necessary to safely assimilate AI-generated snippets into professional codebases. Discuss the role of automated linting, localized test suites, and strict human review protocols as immediate guardrails. Formulate guidelines for establishing developer responsibility when committing code drafted with generative models.
   Key terms: verification strategies, quality gates, automated linting, human-in-the-loop, code review

COMES LATER (do not teach here):
- Model context protocols and architecture (week 1)
```
