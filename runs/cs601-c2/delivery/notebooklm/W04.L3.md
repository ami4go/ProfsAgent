## 2 · Course context (paste as a text source)

```text
COURSE: Software Development using AI (IIIT-Delhi, level 3xx, 3/4-year B.Tech students)
LECTURE: W04.L3 · week 4 · Software requirements and requirements engineering (30 minutes)

LEARNING OUTCOMES (what students must be able to do):
- Outline use cases and system boundaries from unstructured product descriptions using spec-driven development guidelines.

STUDENTS ALREADY KNOW:
- Standards and specification guidelines for use cases (week 4)

THIS LECTURE, PART BY PART:
1. Recap use case standards and spec guidelines (15 min, concept)
   Teaches: Students review the IEEE 830 and UML use case standards, and the spec-driven development guidelines for structuring requirements. They identify the mandatory elements of a use case specification.
   Key terms: IEEE 830, UML use case, spec-driven guidelines, requirements structure, mandatory elements
2. Identify actors and system boundaries (15 min, mechanism)
   Teaches: Students learn a step‑by‑step method to extract actors, primary and secondary, and to draw the system boundary from a raw product description. They practice distinguishing internal vs. external actors.
   Key terms: actor identification, primary actor, secondary actor, system boundary, product description

COMES LATER (do not teach here):
- Spec-driven development frameworks (week 5)
```
