## 2 · Course context (paste as a text source)

```text
COURSE: Software Development using AI (IIIT-Delhi, level 3xx, 3/4-year B.Tech students)
LECTURE: W06.L2 · week 6 · Requirements to executable specifications and code generation (90 minutes)

LEARNING OUTCOMES (what students must be able to do):
- Translate module requirements into executable specifications using spec-driven development frameworks, meeting the stated interface specification for every public method.

STUDENTS ALREADY KNOW:
- Spec-driven development frameworks (week 5)

THIS LECTURE, PART BY PART:
1. Deconstructing Requirements into Public Method Contracts (15 min, concept)
   Teaches: Students will learn how to analyze informal requirements to identify public module methods, parameter contracts, and class invariants. They will establish strict preconditions, postconditions, and interface signatures needed before writing formal specifications.
   Key terms: interface contract, precondition, postcondition, class invariant, method signature
2. Structuring Executable Specifications in Spec-Driven Frameworks (15 min, mechanism)
   Teaches: Students will learn the concrete syntax and structural conventions of spec-driven frameworks such as pytest-bdd or Behave. They will map high-level requirement statements into executable Given-When-Then scenario definitions tied directly to public API hooks.
   Key terms: executable specification, Gherkin, pytest-bdd, step definitions, scenario outline
3. Step-by-Step Translation of Requirements to Executable Specs (20 min, worked example)
   Teaches: Students will follow a complete worked example translating a payment-processing requirement brief into an automated executable specification suite. They will observe how each requirement constraint is systematically formalized into assertion-backed test harnesses that cover all public methods.
   Key terms: step implementation, assertion harness, boundary specification, public API verification
4. Prompt Patterns for Generating Executable Specifications (15 min, concept)
   Teaches: Students will learn effective prompting architectures to instruct LLMs to synthesize spec-driven test suites from unstructured requirements documents. They will configure system instructions and interface schema definitions to eliminate hallucinations in method signatures and types.
   Key terms: prompt engineering, schema anchoring, interface schema, synthetic test generation, hallucination mitigation
5. Hands-on Authoring of Executable Specs from Requirements (25 min, activity)
   Teaches: Students will work in pairs to translate a natural-language requirement specification for a user session manager into an executable specification suite using a BDD framework. They will execute their specs against stub interfaces to confirm that every required public method is bounded by executable assertions.
   Key terms: BDD test suite, interface coverage, failing spec harness, stub interface
```
