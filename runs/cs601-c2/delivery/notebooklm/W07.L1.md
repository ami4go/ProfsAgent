## 2 · Course context (paste as a text source)

```text
COURSE: Software Development using AI (IIIT-Delhi, level 3xx, 3/4-year B.Tech students)
LECTURE: W07.L1 · week 7 · Requirements to executable specifications and code generation (60 minutes)

LEARNING OUTCOMES (what students must be able to do):
- Translate module requirements into executable specifications using spec-driven development frameworks, meeting the stated interface specification for every public method.

STUDENTS ALREADY KNOW:
- Spec-driven development frameworks (week 5)
- Deconstructing Requirements into Public Method Contracts (earlier lecture on this topic)
- Structuring Executable Specifications in Spec-Driven Frameworks (earlier lecture on this topic)
- Step-by-Step Translation of Requirements to Executable Specs (earlier lecture on this topic)
- Prompt Patterns for Generating Executable Specifications (earlier lecture on this topic)
- Hands-on Authoring of Executable Specs from Requirements (earlier lecture on this topic)

THIS LECTURE, PART BY PART:
1. Reviewing Spec Completeness and Interface Compliance (10 min, concept)
   Teaches: Students review criteria for determining whether an executable specification suite is fully complete and airtight before running code generation. They will inspect common edge-case omissions and parameter boundary failures that allow incorrect code to pass specifications.
   Key terms: specification completeness, contract boundary, interface validation, edge-case coverage
2. Spec-Guided AI Code Generation and Validation Loop (15 min, mechanism)
   Teaches: Students will learn the automated feedback loop where LLMs consume executable specifications, generate implementation candidates, and refine code based on failing test traces. They will trace how automated test harness outputs act as prompt feedback to achieve zero interface violations.
   Key terms: test-driven prompt loop, feedback loop, automated refinement, error trace analysis
3. Iterative Code Generation Against Executable Specifications (20 min, activity)
   Teaches: Students will use an AI assistant to generate production code that satisfies the executable specifications authored in the previous session. They will capture runtime test outputs, pass stack traces back to the model, and iteratively guide code generation until 100% of specification steps pass.
   Key terms: code generation, automated self-correction, test-pass criteria, runtime assertion
4. Comparing Conforming Implementations Against Spec Overfitting (15 min, comparison)
   Teaches: Students will compare code that truly satisfies underlying business logic against code that overfits or cheats executable test mocks. They will evaluate techniques such as mutation testing and dynamic property checks to ensure generated code honors public method contracts.
   Key terms: test overfitting, mock cheating, mutation testing, contract fidelity, property-based validation
```
