## 2 · Course context (paste as a text source)

```text
COURSE: Software Development using AI (IIIT-Delhi, level 3xx, 3/4-year B.Tech students)
LECTURE: W10.L2 · week 10 · Automated testing and evaluation mechanisms (90 minutes)

LEARNING OUTCOMES (what students must be able to do):
- Compare automated testing mechanisms and evaluation metrics for AI-native software architectures.

THIS LECTURE, PART BY PART:
1. AI-native architectures and testing challenges (15 min, concept)
   Teaches: Students will identify the distinctive characteristics of AI-native software (data‑driven behavior, non‑determinism, model drift) and explain why traditional testing approaches fall short. They will list at least three testing challenges unique to AI components.
   Key terms: AI-native, non-determinism, model drift, data dependency, test oracle problem
2. Unit testing mechanisms for ML models (15 min, mechanism)
   Teaches: Students will describe property‑based testing, metamorphic testing, and model‑behavior contracts as unit‑level mechanisms for ML models. They will apply one mechanism to a sample classifier and articulate the trade‑off between coverage and oracle cost.
   Key terms: property-based testing, metamorphic testing, behavior contracts, test oracle, coverage
3. Integration testing for AI pipelines (15 min, mechanism)
   Teaches: Students will explain contract testing, data‑drift detection, and end‑to‑end pipeline validation as integration mechanisms. They will compare how each mechanism handles versioned models and evolving data schemas.
   Key terms: contract testing, data drift detection, pipeline validation, model versioning, schema evolution
4. Model quality evaluation metrics (15 min, concept)
   Teaches: Students will define accuracy, fairness, robustness, and calibration metrics and explain when each is appropriate for AI-native systems. They will compute a fairness disparity metric on a provided confusion matrix.
   Key terms: accuracy, fairness, robustness, calibration, disparate impact
5. System-level evaluation metrics (15 min, concept)
   Teaches: Students will describe latency, throughput, cost, and reliability metrics for deployed AI services. They will analyse a scenario to decide which system‑level metric dominates the testing budget.
   Key terms: latency, throughput, cost, reliability, SLA
6. Comparative framework for testing selection (15 min, comparison)
   Teaches: Students will use a decision matrix (mechanism vs. metric vs. risk) to compare and select appropriate testing mechanisms and evaluation metrics for a given AI-native architecture. They will justify their choices with respect to risk tolerance and resource constraints.
   Key terms: decision matrix, risk assessment, resource constraints, trade‑off analysis, selection criteria

COMES LATER (do not teach here):
- Pipeline evaluation mechanisms and metrics (week 11)
- Reliable and safe trustworthy software architectures (week 11)
```
