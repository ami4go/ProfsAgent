# Review quiz · W02.L2 · Coding agents and context engineering

## Recap of the previous lecture (5 min)

1. How do resources differ from tools in Model Context Protocols (MCP)?
   - A. Resources allow models to execute shell commands, whereas tools only provide static files.
   - B. Resources provide passive context data for reading, whereas tools enable dynamic side-effects and execution.
   - C. Resources are defined on the host client, whereas tools reside exclusively on external cloud services.
   - D. Resources require dynamic parameters, whereas tools do not accept input arguments.

2. A developer wants to expose dynamic log streams where the log file URI changes based on a requested user ID parameter. Which MCP construct should they use?
   - A. A parameterized Resource Template with a dynamic URI scheme
   - B. A static tool definition with hardcoded execution parameters
   - C. An environment variable override in the host workspace setting
   - D. A fixed text resource without dynamic URI mapping

3. How does an MCP host validate arguments provided by an LLM before invoking a tool via `tools/call`?
   - A. It validates arguments against the `inputSchema` declared in the server's `tools/list` response.
   - B. It converts all input values to strings automatically without schema checks.
   - C. It forwards the raw prompt to a manual host validation queue.
   - D. It relies on the server to bypass validation if the connection uses stdio.

## Review quiz (5 min)

1. During an agent's execution lifecycle loop, what is the primary role of the agent's scratchpad after executing a tool call?
   - A. To persistently store binary compile artifacts across independent user sessions.
   - B. To track intermediate reasoning state, observations, and tool outputs for subsequent planning steps.
   - C. To bypass sandbox security policies by running unprivileged host scripts.
   - D. To automatically commit and push workspace changes to the remote Git origin branch.

2. Why do coding agent architectures prefer dynamic context engineering mechanisms (like selective file tree pruning) over passing the entire codebase into the prompt?
   - A. Large context windows cause immediate network socket timeouts during API requests.
   - B. Unpruned repository context consumes excessive token budget and can distract the model with irrelevant files.
   - C. Source code files cannot be converted into text tokens due to formatting constraints.
   - D. Selective pruning is strictly required for local static analysis compilers to execute.

3. A developer defines an MCP workspace tool schema but omits parameter validation requirements and required field specifications. What issue is most likely to happen when the agent invokes the tool?
   - A. The agent harness will fail to discover the tool during workspace startup.
   - B. The agent may generate malformed or incomplete argument payloads, leading to execution failures.
   - C. The agent harness runtime will automatically convert the schema into raw shell commands.
   - D. The execution environment will immediately throw a host permission error.

4. An agent workspace exposes over 50 MCP tools simultaneously via global injection, causing high latency, token bloat, and frequent hallucinated tool calls. Which strategy best resolves this trade-off?
   - A. Replace all MCP schemas with free-form natural language prompts in the system message.
   - B. Switch from global tool injection to lazy tool registration based on task context relevance.
   - C. Increase the model's sampling temperature to encourage correct tool selection.
   - D. Remove container isolation so tools execute directly on the local host shell.

## Answers

- Recap 1: **B**: Resources act as passive data providers (like context or read-only files), while tools allow models to run dynamic operations and side-effects. (W02.L1.C1)
- Recap 2: **A**: Resource templates expose parameterized URI schemes, allowing clients to construct dynamic URIs to read specific dynamic context. (W02.L1.C2)
- Recap 3: **A**: Tools define their input requirements via standard JSON Schema (`inputSchema`) during discovery (`tools/list`), which allows strict client/server argument validation. (W02.L1.C3)
- Quiz 1: **B**: The scratchpad maintains internal state tracking, intermediate actions, and tool execution observations so the agent can evaluate progress and plan its next move in the act-observe loop. (W02.L2.C1)
- Quiz 2: **B**: Dynamic context engineering prevents model distraction and keeps token costs manageable by providing only high-relevance code paths instead of full indexing. (W02.L2.C2)
- Quiz 3: **B**: MCP relies on strict JSON schemas to specify argument types and required parameters so the LLM can generate valid tool invocation payloads without missing fields. (W02.L2.C3)
- Quiz 4: **B**: Lazy tool registration dynamically exposes only relevant tools to the context window, eliminating context pollution, lowering token overhead, and reducing hallucinated invocations. (W02.L2.C4)
