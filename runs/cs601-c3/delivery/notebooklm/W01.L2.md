## 2 · Course context (paste as a text source)

```text
COURSE: Software Development using AI (IIIT-Delhi, level 3xx, 3/4-year B.Tech students)
LECTURE: W01.L2 · week 1 · Model context protocols and architecture (60 minutes)

LEARNING OUTCOMES (what students must be able to do):
- Identify the configuration schema and protocol requirements for model context protocols in a supplied developer workspace template.

STUDENTS ALREADY KNOW:
- Developer workflows and AI-assisted coding (week 1)

THIS LECTURE, PART BY PART:
1. Motivation and Core Architecture of Model Context Protocols (15 min, concept)
   Teaches: Explain why standardized context protocols are required to decouple LLM clients from disparate external tools and data sources. Students will understand the client-host-server topology and how it solves the M×N integration bottleneck compared to bespoke API integrations.
   Key terms: Model Context Protocol, Client-Host-Server topology, M×N integration problem, context injection, standardized interface
2. JSON-RPC Message Framing and Transport Layer Mechanisms (15 min, mechanism)
   Teaches: Examine the transport mechanisms used to exchange messages between hosts and context servers, focusing on standard input/output (stdio) and Server-Sent Events (SSE) over HTTP. Students will identify how JSON-RPC 2.0 framing is used to structure requests, responses, and notifications across these transports.
   Key terms: JSON-RPC 2.0, stdio transport, Server-Sent Events (SSE), framing, duplex communication
3. Protocol Initialization Handshake and Capability Negotiation (15 min, mechanism)
   Teaches: Trace the step-by-step lifecycle of protocol initialization, including the client 'initialize' request, server response, and initialized notification. Students will analyze how client and server negotiate supported capabilities such as tools, prompts, resources, and experimental extensions.
   Key terms: initialize handshake, capability negotiation, serverCapabilities, clientCapabilities, initialized notification
4. Comparing Local stdio and Remote SSE Deployment Architectures (15 min, comparison)
   Teaches: Compare the operational and architectural trade-offs between local stdio subprocesses and remote SSE network services. Students will evaluate factors such as local process isolation, network latency, authentication challenges, and persistence requirements.
   Key terms: process lifecycle, remote execution, local subprocess, network latency, bearer authentication

COMES LATER (do not teach here):
- Coding agents and context engineering (week 2)
```
