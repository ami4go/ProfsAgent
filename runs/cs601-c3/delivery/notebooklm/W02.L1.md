## 2 · Course context (paste as a text source)

```text
COURSE: Software Development using AI (IIIT-Delhi, level 3xx, 3/4-year B.Tech students)
LECTURE: W02.L1 · week 2 · Model context protocols and architecture (120 minutes)

LEARNING OUTCOMES (what students must be able to do):
- Identify the configuration schema and protocol requirements for model context protocols in a supplied developer workspace template.

STUDENTS ALREADY KNOW:
- Developer workflows and AI-assisted coding (week 1)
- Motivation and Core Architecture of Model Context Protocols (earlier lecture on this topic)
- JSON-RPC Message Framing and Transport Layer Mechanisms (earlier lecture on this topic)
- Protocol Initialization Handshake and Capability Negotiation (earlier lecture on this topic)
- Comparing Local stdio and Remote SSE Deployment Architectures (earlier lecture on this topic)

THIS LECTURE, PART BY PART:
1. Recap of Protocol Lifecycles and Core Primitives (15 min, concept)
   Teaches: Summarize the JSON-RPC initialization handshake and introduce the three core MCP primitives: resources, prompts, and tools. Students will distinguish between passive data provision (resources) and dynamic model operations (tools).
   Key terms: primitives, passive context, dynamic execution, protocol state, resources vs tools
2. Defining Resources and Resource Templates in Context Schemas (20 min, mechanism)
   Teaches: Explain how context servers expose data via URI schemes and parameterized resource templates. Students will identify the schema fields used to define static text/binary content, MIME types, and dynamic URI-based subscription updates.
   Key terms: resource templates, URI scheme, MIME type, resource subscriptions, readResource
3. Tool Definitions and Dynamic Execution Callbacks (20 min, mechanism)
   Teaches: Examine how servers declare executable tools using JSON Schema for input argument validation. Students will follow the flow from tool discovery (`tools/list`) through host invocation (`tools/call`) to returning structured execution results or errors.
   Key terms: tools/list, tools/call, inputSchema, JSON Schema validation, callToolResult
4. Developer Workspace Configuration Schemas and Server Registration (20 min, concept)
   Teaches: Break down the structure of workspace configuration files, such as `mcpServers` sections in desktop or IDE configuration files. Students will identify mandatory fields including command, args, env variables, and transport settings required to launch context servers.
   Key terms: mcpServers, workspace configuration, environment variables, executable command, schema validation
5. Security Boundaries, Environment Isolation, and Access Control (15 min, concept)
   Teaches: Analyze security risks associated with granting language models access to local files and CLI execution via context protocols. Students will identify mitigation strategies, including sandboxed subprocess execution, prompt injection defense in tool outputs, and explicit user-in-the-loop approvals.
   Key terms: least privilege, user-in-the-loop, prompt injection, subprocess sandboxing, credential isolation
6. Inspecting Configuration Templates for Model Context Protocols (20 min, worked example)
   Teaches: Walk through a supplied developer workspace template to identify configured context servers, missing schema fields, and transport definitions. Students will pinpoint configuration discrepancies such as misconfigured PATHs, missing environment variables, or schema type mismatches.
   Key terms: workspace template, schema verification, configuration audit, server declaration, parameter mapping
7. Diagnosing Protocol Connection Failures and Logging Workflows (10 min, demo)
   Teaches: Demonstrate how to detect and trace common protocol runtime errors using client diagnostic logs and server error codes. Students will evaluate stderr streams, malformed JSON-RPC payloads, and unhandled transport disconnects.
   Key terms: stderr logging, JSON-RPC error codes, transport disconnect, inspector tool, runtime diagnostics

COMES LATER (do not teach here):
- Coding agents and context engineering (week 2)
```
