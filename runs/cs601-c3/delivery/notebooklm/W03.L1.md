## 2 · Course context (paste as a text source)

```text
COURSE: Software Development using AI (IIIT-Delhi, level 3xx, 3/4-year B.Tech students)
LECTURE: W03.L1 · week 3 · Coding agents and context engineering (60 minutes)

LEARNING OUTCOMES (what students must be able to do):
- Configure custom tool integrations within agent workspaces using model context protocols, with all public tests passing and no warnings from the configured static analyser.

STUDENTS ALREADY KNOW:
- Model context protocols and architecture (week 1)
- Anatomy of coding agent workspaces and execution lifecycle (earlier lecture on this topic)
- Context engineering strategies for constrained context windows (earlier lecture on this topic)
- Structuring MCP tool schemas and workspace descriptors (earlier lecture on this topic)
- Evaluating context pollution and tool discovery trade-offs (earlier lecture on this topic)

THIS LECTURE, PART BY PART:
1. Static analysis constraints on agent tool configurations (10 min, concept)
   Teaches: Students will identify common static analyser warnings and strict schema violations that arise when registering MCP server endpoints. They will review rule sets for configuration linters, strict typing of input parameters, and required metadata tags.
   Key terms: static analyser, schema validation, linter warnings, strict typing, manifest configuration
2. Configuring custom MCP tool manifests and execution environments (20 min, mechanism)
   Teaches: Students will write and configure MCP server manifest files to expose custom tools (such as git, linters, or test runners) directly inside an agent workspace. They will configure environment variables, working directory permissions, and execution sandboxes to ensure deterministic agent actions.
   Key terms: manifest configuration, sandboxed execution, environment variables, stdio transport, custom tools, MCP server
3. Validating workspace tool configurations against test suites (20 min, worked example)
   Teaches: Students will walk through setting up and running public integration test suites and static analysis tools against an MCP-integrated agent workspace. They will remediate schema mismatches and failing integration tests until the agent configuration passes cleanly without warnings.
   Key terms: test harness, public tests, static analysis checks, remediation, integration testing, tool verification
4. Diagnosing runtime tool configuration failures in agent workflows (10 min, case study)
   Teaches: Students will examine real-world case studies where subtle tool configuration errors—such as malformed error responses or improper argument defaults—caused an agent to enter infinite loops or crash. They will identify the root cause in the tool manifest and describe how robust configuration prevents runtime divergence.
   Key terms: runtime failure, divergence, infinite loop, error payload, root cause analysis

COMES LATER (do not teach here):
- Custom tool integrations using model context protocols (week 3)
```
