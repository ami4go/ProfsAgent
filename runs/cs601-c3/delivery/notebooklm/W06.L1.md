## 2 · Course context (paste as a text source)

```text
COURSE: Software Development using AI (IIIT-Delhi, level 3xx, 3/4-year B.Tech students)
LECTURE: W06.L1 · week 6 · Spec-driven development frameworks (90 minutes)

LEARNING OUTCOMES (what students must be able to do):
- Translate module requirements into executable specifications using spec-driven development frameworks, meeting the stated interface specification for every public method.

STUDENTS ALREADY KNOW:
- Software requirements and requirements engineering (week 4)
- Foundations of Spec-Driven Development Frameworks (earlier lecture on this topic)
- Anatomy of Executable Specifications and Schemas (earlier lecture on this topic)

THIS LECTURE, PART BY PART:
1. Mapping Natural Language Requirements to Interface Contracts (15 min, worked example)
   Teaches: Students will learn how to systematically convert informal, natural-language module requirements into structured interface contracts. The instructor demonstrates transforming ambiguous functional statements into unambiguous method signatures with specific parameters, return types, and exceptions. Students evaluate how precise specification bounds prevent runtime errors during code generation.
   Key terms: Requirement Decomposition, Interface Signature, Precondition Mapping, Postcondition Mapping, Type Annotations
2. Specifying Preconditions, Postconditions, and Invariants (20 min, mechanism)
   Teaches: Students will formulate explicit invariants, preconditions, and postconditions for every public method in a target module using contract specification frameworks. They will construct concrete validation constraints for input parameters and standard return states. This ensures AI codegen tools generate implementation logic that strictly adheres to the specified contract.
   Key terms: Design by Contract, Precondition, Postcondition, Class Invariant, Boundary Conditions, Validation Rules
3. Automated Test Generation from Executable Specifications (20 min, demo)
   Teaches: Students will observe how spec-driven frameworks automatically synthesize property-based tests and mock servers directly from specification definitions. The demonstration shows running executable specs against sample code to verify whether public methods conform to defined constraints. Students learn to interpret automated test failures resulting from specification violations.
   Key terms: Contract Testing, Property-Based Testing, Mock Generation, Executable Specs, Compliance Verification
4. Translating Complex Module Requirements into Executable Specifications (20 min, worked example)
   Teaches: Students will follow a step-by-step translation of a multi-method business module's requirements into a complete, executable specification file. The worked example walks through defining request validation, error states, and public interface expectations for each method. Students see how to verify that every requirement maps directly to an executable check.
   Key terms: Module Requirements, Specification Synthesis, Public Method Coverage, Error State Specification, Schema Compliance
5. Mitigating Spec Drift and Handling Edge Cases (15 min, discussion)
   Teaches: Students will analyze techniques for maintaining synchronization between evolving executable specifications and generated code over time. They will evaluate trade-offs in spec granularity, identifying when over-specifying hinders LLM code generation flexibility versus under-specifying causing contract breaches. Students discuss strategies to handle edge-case error scenarios within the spec framework.
   Key terms: Spec Drift, Specification Granularity, Edge Case Handling, Schema Evolution, Contract Drift

COMES LATER (do not teach here):
- Requirements to executable specifications and code generation (week 6)
```
