## 2 · Course context (paste as a text source)

```text
COURSE: Software Development using AI (IIIT-Delhi, level 3xx, 3/4-year B.Tech students)
LECTURE: W08.L2 · week 8 · Iterative development logs and software factory outputs (120 minutes)

LEARNING OUTCOMES (what students must be able to do):
- Examine iterative development logs and software factory outputs, identifying at least 2 of the 4 seeded defects, with a proposed fix for each.

STUDENTS ALREADY KNOW:
- Iterative development and loop engineering (week 7)

THIS LECTURE, PART BY PART:
1. Structure of iterative development logs (15 min, concept)
   Teaches: Students will understand the standard sections of an iterative development log (commit metadata, test results, tool invocations) and the schema of software factory output artifacts (build reports, artifact manifests).
   Key terms: log sections, commit metadata, test results, tool invocations, build reports, artifact manifests
2. Seeded defect taxonomy in factory outputs (15 min, concept)
   Teaches: Students will learn the four categories of seeded defects (missing dependency, flaky test, configuration drift, resource leak) and their characteristic signatures in logs and factory outputs.
   Key terms: missing dependency, flaky test, configuration drift, resource leak, defect signatures
3. Parsing and querying log data with CLI tools (15 min, mechanism)
   Teaches: Students will be able to use grep, jq, and custom scripts to extract relevant log entries and factory output fields for defect hunting.
   Key terms: grep, jq, log extraction, field projection, script automation
4. Worked example: detecting a missing dependency defect (15 min, worked example)
   Teaches: Students will follow a step‑by‑step analysis of a sample log where a missing dependency causes a build failure, seeing how to locate the error trace, correlate with the artifact manifest, and formulate a fix.
   Key terms: missing dependency, error trace, artifact manifest, root cause, fix proposal
5. Activity: find two seeded defects in a provided log set (15 min, activity)
   Teaches: Students will individually examine a zip of logs and factory outputs, identify at least two of the four seeded defects, and write a brief fix proposal for each, then submit for peer review.
   Key terms: log set, defect identification, fix proposal, peer review
6. Comparing defect patterns across iterations (15 min, comparison)
   Teaches: Students will compare how the same defect type manifests differently across multiple iterations, noting variations in log verbosity, test flakiness, and factory output anomalies.
   Key terms: iteration comparison, defect manifestation, log verbosity, test flakiness, output anomalies
7. Case study: real‑world factory log analysis (15 min, case study)
   Teaches: Students will review a redacted industry case where iterative logs revealed a configuration drift defect, discussing detection strategy, impact assessment, and remediation steps.
   Key terms: configuration drift, industry case, detection strategy, impact assessment, remediation
8. Discussion: best practices for proposing fixes (15 min, discussion)
   Teaches: Students will evaluate fix proposals for completeness, testability, and regression risk, and agree on a checklist for future defect remediation in iterative loops.
   Key terms: fix completeness, testability, regression risk, remediation checklist

COMES LATER (do not teach here):
- Software factories and execution trace analysis (week 9)
```
