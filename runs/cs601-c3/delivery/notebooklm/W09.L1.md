## 2 · Course context (paste as a text source)

```text
COURSE: Software Development using AI (IIIT-Delhi, level 3xx, 3/4-year B.Tech students)
LECTURE: W09.L1 · week 9 · Software factories and execution trace analysis (150 minutes)

LEARNING OUTCOMES (what students must be able to do):
- Analyze execution traces produced by coding agents during iterative loop engineering tasks, for a supplied log file of at most 2000 lines, identifying at least three distinct failure causes with supporting log evidence.

STUDENTS ALREADY KNOW:
- Iterative development logs and software factory outputs (week 8)

THIS LECTURE, PART BY PART:
1. Execution traces in software factories (15 min, concept)
   Teaches: Students learn what execution traces are, how coding agents emit them during iterative loop engineering, and why they are essential for diagnosing failures in software factories.
   Key terms: execution trace, software factory, coding agent, iterative loop, diagnostics
2. Log structure and iteration markers (15 min, mechanism)
   Teaches: Students examine the standardized format of iterative development logs, including timestamps, iteration IDs, tool calls, and error markers, enabling systematic navigation of up to 2000 lines.
   Key terms: log format, iteration ID, timestamp, tool call, error marker
3. Typical failure patterns in agent traces (15 min, concept)
   Teaches: Students identify three recurring failure categories—environment misconfiguration, dependency resolution errors, and logic regressions—and learn the trace signatures that distinguish each.
   Key terms: environment misconfiguration, dependency resolution, logic regression, trace signature, failure category
4. Trace collection and parsing tooling (15 min, demo)
   Teaches: Students watch a live demonstration of the factory's trace collector, log aggregator, and a Python script that parses raw logs into structured JSON for analysis.
   Key terms: trace collector, log aggregator, parser script, JSON output, automation
5. Worked example: environment misconfiguration (15 min, worked example)
   Teaches: Students follow a step‑by‑step analysis of a 500‑line trace, locating missing environment variables, correlating error codes, and citing exact log lines as evidence for the first failure cause.
   Key terms: environment variable, error code, log evidence, correlation, step‑by‑step
6. Worked example: dependency resolution failure (15 min, worked example)
   Teaches: Students trace a version conflict across iterations, observe repeated fetch retries, and extract the specific dependency graph lines that prove the second failure cause.
   Key terms: version conflict, fetch retry, dependency graph, iteration diff, evidence extraction
7. Worked example: logic regression detection (15 min, worked example)
   Teaches: Students compare successive iteration outputs, spot a behavioral change in test results, and pinpoint the commit diff lines that constitute the third failure cause with supporting log excerpts.
   Key terms: behavioral change, test result diff, commit diff, log excerpt, regression
8. Comparing failure causes across traces (15 min, comparison)
   Teaches: Students contrast the three failure signatures side‑by‑side, evaluate their frequency and impact, and practice ranking them by severity using a structured rubric.
   Key terms: signature comparison, frequency, impact, severity rubric, ranking
9. Activity: analyze full 2000‑line log (15 min, activity)
   Teaches: In pairs, students receive a 2000‑line factory log, apply the parsing script, identify at least three distinct failure causes, and record supporting log line numbers for each.
   Key terms: pair work, 2000‑line log, parsing script, failure identification, evidence recording
10. Discussion: reporting and best practices (15 min, discussion)
   Teaches: Students present their findings, critique evidence quality, discuss how to automate failure‑cause detection, and outline a checklist for future trace analyses.
   Key terms: findings presentation, evidence critique, automation ideas, checklist, continuous improvement

COMES LATER (do not teach here):
- Testing and validation in iterative development (week 9)
```
