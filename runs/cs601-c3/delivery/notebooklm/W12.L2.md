## 2 · Course context (paste as a text source)

```text
COURSE: Software Development using AI (IIIT-Delhi, level 3xx, 3/4-year B.Tech students)
LECTURE: W12.L2 · week 12 · Deployment and reliability metric evaluation (90 minutes)

LEARNING OUTCOMES (what students must be able to do):
- Evaluate deployment and reliability metrics for a supplied multi-component software project, demonstrating live, with 2 scenario walkthroughs chosen by the evaluator.

STUDENTS ALREADY KNOW:
- Reliable and safe trustworthy software architectures (week 11)

THIS LECTURE, PART BY PART:
1. Key deployment metrics overview (15 min, concept)
   Teaches: Students learn the definitions of latency, error rate, throughput, deployment frequency, and rollback time. They understand how each metric signals the health of a deployment pipeline.
   Key terms: latency, error rate, throughput, deployment frequency, rollback time
2. Reliability metrics and SLOs (15 min, concept)
   Teaches: Students define availability, MTBF, MTTR, SLO, SLI, and error budget. They see how these metrics quantify system reliability and guide release decisions.
   Key terms: availability, MTBF, MTTR, SLO, SLI, error budget
3. Instrumenting a multi-component system with OpenTelemetry (15 min, mechanism)
   Teaches: Students follow the steps to add traces, metrics, and logs across services using OpenTelemetry SDKs. They configure exporters to Prometheus and verify that data flows correctly.
   Key terms: OpenTelemetry, traces, metrics, logs, Prometheus exporter, context propagation
4. Live dashboard walkthrough with Grafana (15 min, demo)
   Teaches: Students watch the creation of a Grafana dashboard that visualizes deployment and reliability metrics. They learn to set alert rules on error‑budget burn rate.
   Key terms: Grafana, dashboard, panels, alerting, error budget
5. Scenario walkthrough 1: load‑test and failure injection (15 min, worked example)
   Teaches: The instructor runs a k6 load test against the sample project, injects a service failure with Chaos Mesh, and evaluates whether SLOs remain satisfied. Students observe metric shifts in real time.
   Key terms: k6, load test, failure injection, Chaos Mesh, SLO evaluation
6. Student activity: evaluate metrics on supplied project (15 min, activity)
   Teaches: In pairs, students use the instrumented project to compute deployment and reliability metrics, decide if a release meets the defined SLOs, and present their go/no‑go recommendation for peer review.
   Key terms: metric calculation, release decision, presentation, peer review
```
