# Review quiz · W01.L2 · Model context protocols and architecture

   - A. Developers no longer need to write design specifications or document interfaces.

## Review quiz (5 min)

1. How does adopting a Client-Host-Server topology with Model Context Protocol (MCP) solve the M×N integration problem for LLM applications?
   - A. It removes the need for tool invocation by having the LLM directly execute local code.
   - B. It converts all tool communication payloads from JSON into binary protocols.
   - C. It replaces custom integrations with a standardized interface between host environments and external servers.
   - D. It mandates a single centralized database that all LLM clients and data sources must share.

2. In local MCP communication using the stdio transport layer, how are requests and responses framed and transmitted?
   - A. As raw binary streams sent across shared system memory
   - B. As protocol buffers transmitted via a WebSockets connection
   - C. As JSON-RPC 2.0 structured messages sent over standard input and output streams
   - D. As HTTP POST requests with Server-Sent Events headers

3. During the MCP initialization handshake, what is the primary role of capability negotiation?
   - A. To determine whether messages should switch from standard text to compressed binary format
   - B. To verify API keys and encrypt the stdio communication channel
   - C. To dynamically allocate hardware CPU and memory limits for the server process
   - D. To allow client and server to declare supported features like tools, resources, and prompts before starting operations

4. A engineering team is choosing between local stdio and remote SSE deployments for an MCP server accessing a shared cloud database. Which trade-off makes remote SSE the better choice for this scenario?
   - A. Remote SSE eliminates network latency compared to local subprocess execution.
   - B. Remote SSE allows central network deployment and bearer authentication, avoiding duplicate local process management on each developer machine.
   - C. Local stdio cannot handle JSON-RPC 2.0 message framing over local sub-processes.
   - D. Local stdio requires opening exposed incoming network ports on host machines.

## Answers

- Recap 1: **D**: AI-augmented workflows transform the traditional linear edit-compile-debug loop into continuous speculative drafting, where developers refine prompts and evaluate model suggestions iteratively. (W01.L1.C1)
- Recap 2: **D**: The local IDE extension collects real-time editor state such as local buffer snippets, cursor position, and telemetry before handing them off to an orchestrator for prompt assembly. (W01.L1.C2)
- Recap 3: **B**: Expanding the context scope gives the model useful ambient information, but processing more tokens increases prompt processing and overall inference latency. (W01.L1.C3)
- Quiz 1: **C**: MCP introduces a standardized client-host-server interface, decoupling LLM clients from disparate external tools and reducing M×N bespoke integrations into an M+N architecture. (W01.L2.C1)
- Quiz 2: **C**: The stdio transport mechanism uses standard input/output streams to frame and exchange JSON-RPC 2.0 structured requests, responses, and notifications between host and subprocess. (W01.L2.C2)
- Quiz 3: **D**: Capability negotiation occurs during initialization so both client and server can declare supported features (such as resources, prompts, and tools) and ensure compatibility before requests begin. (W01.L2.C3)
- Quiz 4: **B**: Remote SSE services allow central deployment, network-based authentication, and persistence across users, whereas stdio is designed for local subprocess isolation on a single host machine. (W01.L2.C4)
