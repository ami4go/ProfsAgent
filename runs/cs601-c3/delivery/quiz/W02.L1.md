## Review quiz (10 min)

1. How do resources differ from tools in Model Context Protocols (MCP)?
   - A. Resources provide passive context data for reading, whereas tools enable dynamic side-effects and execution.
   - B. Resources allow models to execute shell commands, whereas tools only provide static files.
   - C. Resources require dynamic parameters, whereas tools do not accept input arguments.
   - D. Resources are defined on the host client, whereas tools reside exclusively on external cloud services.

2. A developer wants to expose dynamic log streams where the log file URI changes based on a requested user ID parameter. Which MCP construct should they use?
   - A. An environment variable override in the host workspace setting
   - B. A fixed text resource without dynamic URI mapping
   - C. A static tool definition with hardcoded execution parameters
   - D. A parameterized Resource Template with a dynamic URI scheme

3. How does an MCP host validate arguments provided by an LLM before invoking a tool via `tools/call`?
   - A. It validates arguments against the `inputSchema` declared in the server's `tools/list` response.
   - B. It relies on the server to bypass validation if the connection uses stdio.
   - C. It converts all input values to strings automatically without schema checks.
   - D. It forwards the raw prompt to a manual host validation queue.

4. Which mandatory fields are required in an `mcpServers` workspace configuration entry to launch a local subprocess context server?
   - A. `uriTemplate` and `mimeType` to specify context encoding formats
   - B. `promptInjection` and `sandboxMode` to set protocol execution boundaries
   - C. `toolsList` and `callResult` to map server callback functions
   - D. `command` and `args` to specify the executable binary and its launch arguments

5. An external tool returns raw text output that contains malicious instructions designed to hijack the LLM context. What is the most effective mitigation strategy?
   - A. Disabling all logging from stderr to suppress error messages
   - B. Running the server in high-privilege administrator mode to override unexpected errors
   - C. Hardcoding database secrets directly inside the shared client configuration file
   - D. Enforcing user-in-the-loop explicit approvals before executing sensitive downstream tools

6. A student configures an MCP server in `mcpServers` with `"command": "python"`, but the server immediately terminates because it lacks the script path and API key. Which part of the configuration template needs fixing?
   - A. Changing the server protocol registration from JSON-RPC to XML
   - B. Removing the `command` attribute and replacing it with a static `uri` scheme
   - C. Updating the tool's JSON Schema type definitions from string to boolean
   - D. Adding the script path under `args` and the required API key key-values under `env`

7. A local MCP server process fails during initialization without sending a JSON-RPC error response. Where should a developer look to diagnose the startup error?
   - A. The server's public `resources/list` payload
   - B. The client host's static UI rendering logs
   - C. The subprocess `stderr` log stream of the context server
   - D. The `inputSchema` section of the prompt catalog

## Answers

- Recap 1: **C**: MCP introduces a standardized client-host-server interface, decoupling LLM clients from disparate external tools and reducing M×N bespoke integrations into an M+N architecture. (W01.L2.C1)
- Recap 2: **C**: The stdio transport mechanism uses standard input/output streams to frame and exchange JSON-RPC 2.0 structured requests, responses, and notifications between host and subprocess. (W01.L2.C2)
- Recap 3: **D**: Capability negotiation occurs during initialization so both client and server can declare supported features (such as resources, prompts, and tools) and ensure compatibility before requests begin. (W01.L2.C3)
- Quiz 1: **A**: Resources act as passive data providers (like context or read-only files), while tools allow models to run dynamic operations and side-effects. (W02.L1.C1)
- Quiz 2: **D**: Resource templates expose parameterized URI schemes, allowing clients to construct dynamic URIs to read specific dynamic context. (W02.L1.C2)
- Quiz 3: **A**: Tools define their input requirements via standard JSON Schema (`inputSchema`) during discovery (`tools/list`), which allows strict client/server argument validation. (W02.L1.C3)
- Quiz 4: **D**: Subprocess server declarations in `mcpServers` require at minimum the executable `command` and optional command-line `args` (along with `env`) to start the server. (W02.L1.C4)
- Quiz 5: **D**: Requiring explicit human approval (user-in-the-loop) for sensitive side-effects stops prompt injections contained in untrusted tool responses from executing unchecked actions. (W02.L1.C5)
- Quiz 6: **D**: Command-line arguments (like script files) must be passed via the `args` array and environment parameters (like API keys) must be set in the `env` dictionary of the configuration schema. (W02.L1.C6)
- Quiz 7: **C**: Runtime crashes, missing dependencies, or syntax errors in local server binaries output details directly to the subprocess standard error (`stderr`) stream. (W02.L1.C7)
