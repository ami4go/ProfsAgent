## Review quiz (5 min)

1. A static analyzer flags a warning on an MCP server manifest because a registered tool's input parameter lacks an explicit schema type. Why is strict typing enforced in tool manifests?
   - A. It removes the requirement for sandboxed execution environments.
   - B. It prevents the stdio transport layer from dropping requests silently.
   - C. It ensures the agent receives unambiguous parameter schemas to generate correctly structured tool calls.
   - D. It allows static analyzers to automatically execute unit tests on the tool binary.

2. You are configuring an MCP server manifest to expose a custom test runner in an agent workspace, but the tool fails because it cannot locate installed system binaries. How should you fix the manifest configuration?
   - A. Explicitly define the execution environment variables (such as PATH) and directory permissions in the manifest.
   - B. Disable sandboxed execution to give the agent host-level root access.
   - C. Increase the log level of the static analyzer to bypass missing binary warnings.
   - D. Switch the communication transport from stdio to HTTP REST.

3. During integration testing of a workspace tool configuration, all static analysis checks pass, but the public test suite fails due to a schema mismatch between expected and actual tool response structures. How should this failure be remediated?
   - A. Update the tool manifest's response schema to accurately match the tool's actual output payload.
   - B. Bypass static analysis checks so the pipeline ignores output verification.
   - C. Replace stdio transport with manual human-in-the-loop validation.
   - D. Suppress the failing integration assertions in the test harness.

4. An agent enters an infinite loop repeatedly calling a custom git tool. Log analysis shows that whenever an execution fails, the tool returns a generic non-zero exit status without an explicit error payload. What is the root cause of this divergence?
   - A. The stdio transport buffer overflowed from unbuffered binary logs.
   - B. The tool manifest lacked explicit timeout configurations for sandboxed execution.
   - C. Missing structured error details prevent the agent from understanding the failure context, causing repetitive retry attempts.
   - D. The static analyzer failed to inspect working directory permissions at startup.

## Answers

- Recap 1: **A**: The scratchpad functions as short-term memory within the agent lifecycle loop, enabling the model to retain intermediate context, track progress, and consume tool observations before taking the next action. (W02.L2.C1)
- Recap 2: **C**: Pruning irrelevant directories and files reduces context pollution and keeps token usage within limits, preventing the LLM from getting distracted by unrelated codebase noise. (W02.L2.C2)
- Recap 3: **B**: MCP tool discovery relies on structured JSON schemas; explicitly defining required parameters and data types ensures the harness validates inputs before invoking the tool. (W02.L2.C3)
- Quiz 1: **C**: Strict typing in manifests prevents schema ambiguity, ensuring LLM agents construct valid, correctly typed arguments when invoking registered tools. (W03.L1.C1)
- Quiz 2: **A**: Configuring execution environment variables like PATH within the tool manifest ensures deterministic execution by granting the tool access to required system binaries within its sandbox. (W03.L1.C2)
- Quiz 3: **A**: Remediating schema mismatches requires updating the manifest definitions so that actual tool outputs cleanly align with the expected response schema validated by integration tests. (W03.L1.C3)
- Quiz 4: **C**: Subtle configuration flaws like missing or malformed error payloads prevent the agent from diagnosing execution failures, causing runtime divergence such as infinite retry loops. (W03.L1.C4)
