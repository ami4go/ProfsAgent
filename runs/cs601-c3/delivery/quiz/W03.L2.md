# Review quiz · W03.L2 · Custom tool integrations using model context protocols

## Recap of the previous lecture (5 min)

   - A. It removes the requirement for sandboxed execution environments.
   - B. It prevents the stdio transport layer from dropping requests silently.
   - C. It ensures the agent receives unambiguous parameter schemas to generate correctly structured tool calls.
   - D. It allows static analyzers to automatically execute unit tests on the tool binary.

2. You are configuring an MCP server manifest to expose a custom test runner in an agent workspace, but the tool fails because it cannot locate installed system binaries. How should you fix the manifest configuration?
   - A. Explicitly define the execution environment variables (such as PATH) and directory permissions in the manifest.
   - B. Disable sandboxed execution to give the agent host-level root access.
   - C. Increase the log level of the static analyzer to bypass missing binary warnings.
   - D. Switch the communication transport from stdio to HTTP REST.

3. During integration testing of a workspace tool configuration, all static analysis checks pass, but the public test suite fails due to a schema mismatch between expected and actual tool response structures. How should this failure be remediated?
   - A. Update the tool manifest's response schema to accurately match the tool's actual output payload.
   - B. Bypass static analysis checks so the pipeline ignores output verification.
   - C. Replace stdio transport with manual human-in-the-loop validation.
   - D. Suppress the failing integration assertions in the test harness.

## Review quiz (10 min)

1. In the Model Context Protocol (MCP) architecture, what is the primary role of the MCP Client when an LLM agent needs to interact with external tools?
   - A. It acts as an intermediary inside the host application, managing session transport and routing messages to the MCP Server.
   - B. It hosts external database storage for agent execution logs.
   - C. It directly executes the external tool's logic inside the client process.
   - D. It generates natural language responses and sends them directly to the end user.

2. Which JSON-RPC 2.0 method is sent by an MCP client over standard input/output streams to request the list of exposed tools from an MCP server?
   - A. tools/call
   - B. mcp/discover
   - C. tools/list
   - D. system/getTools

3. An LLM agent frequently passes invalid floating-point numbers to a tool parameter `port_number` that expects a valid positive port integer. How should you update the tool's `inputSchema` to enforce valid input?
   - A. Set `type` to `"string"` so the LLM converts the port number to a string before calling.
   - B. Add a prompt hint inside the parameter's text description asking the agent to avoid decimals.
   - C. Mark the `port_number` property as optional so the server fills in a default integer when validation fails.
   - D. Set the `type` of `port_number` to `"integer"`, add `"minimum": 1`, and include `port_number` in the `required` array.

4. When implementing an MCP server using an official SDK, how are local functions typically registered as callable tools exposed to the client?
   - A. By declaring the function names in an external environment variable.
   - B. By applying SDK decorator syntax (e.g., `@mcp.tool()`) or registration functions over tool handlers.
   - C. By manually parsing stdin buffers with regex inside a custom event loop.
   - D. By writing standard REST API controllers and mapping them to HTTP POST routes.

5. A custom MCP tool function executes a local file read operation. What structured object format should the function return to pass the text output back to the client over stdio?
   - A. A simple boolean value indicating whether the read succeeded.
   - B. A raw unformatted string printed directly to process stdout.
   - C. A standard HTTP 200 OK response wrapper.
   - D. A `CallToolResult` structure containing formatted content blocks such as `TextContent`.

6. You have compiled a custom MCP server executable. How should the agent workspace configuration file be updated so that the host application automatically launches and connects to the server?
   - A. Move the executable to the root system folder `/bin` and restart the machine.
   - B. Add a system environment variable named `DISCOVER_MCP_SERVERS=true`.
   - C. Embed the binary byte sequence directly inside the workspace prompt file.
   - D. Define an entry inside the `mcpServers` object with the server executable command and any required command-line arguments.

7. During execution, a tool encounters a runtime error because a user-requested file is missing. How should the MCP server communicate this failure back to the LLM agent?
   - A. Throw an unhandled exception to crash the stdio process so the client detects the crash.
   - B. Send a JSON-RPC transport error code `-32600` (Invalid Request) back over the stream.
   - C. Return an empty success response so the LLM assumes the file contained no text.
   - D. Return a `CallToolResult` with `isError` set to `true` and the error message inside the text content block.

## Answers

- Recap 1: **C**: Strict typing in manifests prevents schema ambiguity, ensuring LLM agents construct valid, correctly typed arguments when invoking registered tools. (W03.L1.C1)
- Recap 2: **A**: Configuring execution environment variables like PATH within the tool manifest ensures deterministic execution by granting the tool access to required system binaries within its sandbox. (W03.L1.C2)
- Recap 3: **A**: Remediating schema mismatches requires updating the manifest definitions so that actual tool outputs cleanly align with the expected response schema validated by integration tests. (W03.L1.C3)
- Quiz 1: **A**: The MCP Client resides within the host application (like an IDE or agent workspace) and manages communication and transport protocol handlers between the host and external MCP Servers. (W03.L2.C1)
- Quiz 2: **C**: In the MCP JSON-RPC 2.0 specification, `tools/list` is the standard method sent by the client to perform tool discovery on the server. (W03.L2.C2)
- Quiz 3: **D**: JSON Schema permits structural and type constraints such as setting `"type": "integer"` and numerical limits (`"minimum": 1`) inside `inputSchema` to prevent bad LLM tool invocations. (W03.L2.C3)
- Quiz 4: **B**: Official MCP SDKs simplify development by providing decorators or server handlers that automatically parse incoming JSON payloads into function arguments. (W03.L2.C4)
- Quiz 5: **D**: MCP tool handlers return standard structures like `CallToolResult` populated with structured content items like `TextContent` to report output. (W03.L2.C5)
- Quiz 6: **D**: Workspace settings configure custom MCP servers by declaring them under the `mcpServers` dictionary key with the executable `command`, `args`, and `env` parameters. (W03.L2.C6)
- Quiz 7: **D**: Tool execution runtime failures should be returned gracefully in the result payload with `isError: true` so the agent can read the error text and attempt recovery. (W03.L2.C7)
