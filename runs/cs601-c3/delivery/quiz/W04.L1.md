# Review quiz · W04.L1 · Custom tool integrations using model context protocols

## Review quiz (0 min)

1. A developer builds an MCP server function that receives payloads from an LLM call. The static analyzer throws a warning regarding untyped JSON schema bindings. Why is this flagged as a risk for production tool integration?
   - A. Untyped bindings prevent the agent workspace from opening network connections.
   - B. Untyped bindings allow unexpected payload structures from the LLM to cause unhandled runtime errors.
   - C. The linter requires all JSON schema payloads to be encrypted prior to parsing.
   - D. Static analyzers cannot parse async functions unless parameters are strings.

2. While writing an async tool handler for an MCP server, the static analyzer reports an 'unhandled promise' warning on a secondary network request. How should you resolve this warning to ensure code safety?
   - A. Convert the entire tool execution context to synchronous code.
   - B. Explicitly await the promise or attach a catch block to handle potential rejections cleanly.
   - C. Suppress the linter warning using a broad rule suppression comment.
   - D. Move the request into an inline string evaluated at runtime.

3. In an agent workspace pipeline, all functional integration tests for an MCP tool pass, yet the build fails static validation. What is the most likely cause based on production standards?
   - A. The test harness requires manual user confirmation for each tool execution.
   - B. The server implementation contains unresolved static analysis warnings.
   - C. The agent workspace environment only supports synchronous tool integration.
   - D. Integration tests cannot run alongside linter checks.

4. An integration test suite fails when passing null edge-case inputs to a newly configured MCP tool. How should you fix the tool setup to ensure all tests pass cleanly without warnings?
   - A. Configure the LLM agent to automatically retry when a null input occurs.
   - B. Skip edge-case test execution inside the test harness configuration.
   - C. Hardcode fallback default strings inside the agent's system prompt.
   - D. Strictly define and validate missing/null fields within the tool's JSON schema and handler types.

## Answers

- Quiz 1: **B**: Untyped JSON bindings allow malformed or unexpected responses from the LLM to bypass type checks, potentially causing runtime crashes in the tool handler. (W04.L1.C1)
- Quiz 2: **B**: Explicitly awaiting promises or handling rejections ensures unhandled errors do not cause silent failures or unhandled promise rejections in production. (W04.L1.C1)
- Quiz 3: **B**: Production-grade tool configuration requires both all functional tests to pass and zero static analysis warnings from configured linters. (W04.L1.C2)
- Quiz 4: **D**: Aligning static type definitions and JSON schemas to handle optional or null values ensures edge-case inputs pass integration tests safely. (W04.L1.C2)
