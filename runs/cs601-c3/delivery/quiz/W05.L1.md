# Review quiz · W05.L1 · Software requirements and requirements engineering

## Recap of the previous lecture (5 min)

1. According to standard spec-driven guidelines and use case standards, which element is mandatory in a formal use case specification?
   - A. Internal database schema design
   - B. Target programming language version
   - C. Hardware memory allocation limits
   - D. Primary actor and goal statement

2. An e-commerce application sends transaction verification requests to an external payment gateway during checkout. How is the external payment gateway classified in this system's use case model?
   - A. Primary actor inside the system boundary
   - B. Use case action within the system process
   - C. Secondary external actor outside the system boundary
   - D. Internal actor within the system boundary

## Review quiz (10 min)

1. You are parsing an unstructured product description for an e-commerce platform. Which requirement statement correctly represents a precondition in the functional template?
   - A. The item stock count is decremented in the inventory database.
   - B. The user clicks the Submit Order button on the confirmation page.
   - C. The user must have an active account with a verified email address before initiating checkout.
   - D. The system sends a confirmation email after payment succeeds.

2. A developer writes the following step in a main success scenario: '3. System authenticates user credentials, generates a session token, and updates user profile statistics.' Why does this step violate spec guidelines?
   - A. It combines multiple operations into one step instead of keeping steps atomic and observable.
   - B. Main success scenarios must only contain user actions, not system responses.
   - C. It references a database token which is forbidden in requirements.
   - D. It lacks an actor name in the sentence structure.

3. In a flight booking use case, step 4 of the main success scenario is 'User submits credit card details.' How should an expired card error be documented to maintain clear traceability?
   - A. Add an extension branch tied to step 4, designated as '4a. Credit card is expired.'
   - B. List card expiration checks in the use case postconditions.
   - C. Create a completely independent use case titled 'Handle Expired Credit Card'.
   - D. Embed an IF-THEN conditional block directly inside step 4 of the main success scenario.

4. While drawing a UML context diagram for a course registration system, a student places the university's central OAuth identity provider inside the system boundary box. What is wrong with this placement?
   - A. Context diagrams cannot include third-party integrations.
   - B. Software systems belong inside the boundary; only human users are drawn outside.
   - C. Identity providers should only be represented in database ER diagrams.
   - D. External services and identity providers must be drawn outside the system boundary as external actors.

5. A software team is planning the first release of a healthcare app. A proposed use case allows users to customize the UI accent color scheme. Under MoSCoW prioritization for launch, how should this use case be classified?
   - A. Should Have
   - B. Must Have
   - C. Could Have
   - D. Won't Have

6. During a use case review, an auditor flags the step: 'System processes the patient record fast and securely.' Which quality checklist criterion does this step fail?
   - A. Precondition validity
   - B. Testability
   - C. Completeness
   - D. Actor identification

7. In a spec-driven development pipeline, how does a use case main success scenario directly map to downstream testing artifacts?
   - A. It maps to executable feature files containing Given-When-Then acceptance criteria.
   - B. It becomes infrastructure provisioning scripts.
   - C. It transforms into low-level architectural class diagrams.
   - D. It converts into database schema migration files.

8. A peer review of a banking application specification shows 'Junior Admin', 'Senior Admin', and 'System Lead' performing identical steps in the 'Reset Password' use case. What pitfall should be corrected?
   - A. Vague step wording
   - B. Boundary leakage
   - C. Missing exception handling
   - D. Actor overload

## Answers

- Recap 1: **D**: Standard use case specifications mandate identifying functional elements such as the primary actor and their intended goal rather than technical implementation details. (W04.L3.C1)
- Recap 2: **C**: External services that interface with the system to fulfill a request are categorized as secondary actors residing outside the system boundary. (W04.L3.C2)
- Quiz 1: **C**: A precondition defines the mandatory state that must hold true before the user goal or action can begin, such as having a verified active account. (W05.L1.C1)
- Quiz 2: **A**: Spec-driven guidelines require each step in a main success scenario to be atomic and observable rather than bundling multiple system actions into a single step. (W05.L1.C2)
- Quiz 3: **A**: Extensions use the numbering scheme of the main scenario step they branch from (e.g., 4a) to preserve traceability to the exact point of divergence. (W05.L1.C3)
- Quiz 4: **D**: The system boundary separates the system being built from external systems and actors, which must be placed outside the boundary box. (W05.L1.C4)
- Quiz 5: **C**: A cosmetic feature like UI customization offers non-essential value and is classified as 'Could Have' (desirable but not critical for the first release). (W05.L1.C5)
- Quiz 6: **B**: Ambiguous, subjective terms like 'fast' and 'securely' cannot be verified objectively, failing the testability check. (W05.L1.C6)
- Quiz 7: **A**: Use case scenarios map directly to feature files with acceptance criteria (Given-When-Then format) in spec-driven testing frameworks. (W05.L1.C7)
- Quiz 8: **D**: Listing multiple separate actor titles for identical interactions creates actor overload; they should be consolidated into a single generalized actor role. (W05.L1.C9)
