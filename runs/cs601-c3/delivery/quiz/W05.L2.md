# Review quiz · W05.L2 · Spec-driven development frameworks

## Review quiz (0 min)

1. How does Spec-Driven Development (SDD) fundamentally differ from traditional Test-Driven Development (TDD)?
   - A. SDD eliminates the need for testing entirely by relying on static evaluation.
   - B. SDD decouples the interface contract from language-specific code using formal specs as the single source of truth.
   - C. TDD relies on machine-readable schemas, whereas SDD relies strictly on manual code reviews.
   - D. SDD requires implementation code to be written before defining interface contracts.

2. Why are executable specifications particularly useful when integrating Large Language Models (LLMs) into the development workflow?
   - A. They allow LLMs to automatically write documentation without checking data types.
   - B. They translate natural language requests directly into machine assembly without code.
   - C. They provide an unambiguous machine-readable benchmark for LLMs to enforce architectural and interface consistency.
   - D. They eliminate the need for prompt engineering by running code directly in the database.

3. What is the primary benefit of defining input constraints and response schemas in frameworks like JSON Schema or TypeSpec before writing implementation code?
   - A. It guarantees that database queries execute with optimal performance at runtime.
   - B. It eliminates the need for HTTP request handling in web frameworks.
   - C. It automatically deploys application code to production cloud servers.
   - D. It enables automated contract validation of public interfaces before any backend code is generated.

4. What role do preconditions and postconditions play within an executable specification schema?

## Answers

- Quiz 1: **B**: SDD establishes formal, machine-readable specifications as the single source of truth prior to implementation, decoupling interface contracts from language-specific test scripts. (W05.L2.C1)
- Quiz 2: **C**: Executable specifications provide a clear, machine-readable single source of truth that LLMs and static analyzers use to validate and enforce API interface consistency. (W05.L2.C1)
- Quiz 3: **D**: Machine-readable schemas define public interface signatures and constraints upfront, allowing automated validation of contracts prior to writing implementation code. (W05.L2.C2)
- Quiz 4: **They define structural input constraints and expected response signatures, enabling automated contract validation before code implementation.**: Preconditions and postconditions explicitly constrain allowed inputs and valid output structures within machine-readable specs, ensuring interface compliance automatedly. (W05.L2.C2)
