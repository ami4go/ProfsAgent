# Review quiz · W06.L1 · Spec-driven development frameworks

## Recap of the previous lecture (5 min)

1. How does Spec-Driven Development (SDD) fundamentally differ from traditional Test-Driven Development (TDD)?
   - A. SDD eliminates the need for testing entirely by relying on static evaluation.
   - B. SDD decouples the interface contract from language-specific code using formal specs as the single source of truth.
   - C. TDD relies on machine-readable schemas, whereas SDD relies strictly on manual code reviews.
   - D. SDD requires implementation code to be written before defining interface contracts.

2. What is the primary benefit of defining input constraints and response schemas in frameworks like JSON Schema or TypeSpec before writing implementation code?
   - A. It guarantees that database queries execute with optimal performance at runtime.
   - B. It eliminates the need for HTTP request handling in web frameworks.
   - C. It automatically deploys application code to production cloud servers.
   - D. It enables automated contract validation of public interfaces before any backend code is generated.

## Review quiz (10 min)

1. You need to convert an informal requirement—'Calculate discount based on user age and loyalty points, failing gracefully on invalid inputs'—into an unambiguous contract for an AI code generator. Which interface specification best achieves this?
   - A. def calculate_discount(age: int, points: int) -> float (raises ValueError for negative inputs)
   - B. def calculate_discount(age: str, points: str) -> int
   - C. def calculate_discount(age, points)
   - D. def calculate_discount(user_info: dict) -> any

2. In a Design by Contract specification for a BankAccount class, a developer asserts that `balance >= 0` must evaluate to true before and after any public method execution. What type of contract constraint is this?
   - A. Class Invariant
   - B. Precondition
   - C. Postcondition
   - D. Input Boundary Condition

3. An automated testing tool reads an executable contract and generates hundreds of randomized integer inputs to verify that a sorting method always returns a sorted list. Which technique is the framework demonstrating?
   - A. Static Code Linting
   - B. Mock Server Simulation
   - C. Property-Based Test Generation
   - D. Manual Unit Testing

4. When translating a multi-method payment gateway module into an executable specification file, how can a developer ensure complete requirement coverage across public interfaces?
   - A. Combine all requirements into a single generic interface signature
   - B. Define request validation schemas, expected return types, and explicit error states for every public method
   - C. Write informal docstrings describing the business workflow inside the code file
   - D. Rely on the LLM to dynamically generate edge-case validation checks at runtime

5. A development team notices that an LLM code generator frequently fails to produce working code because the executable specification defines exact private helper variable names and internal loop mechanics. What specification design mistake did the team make?
   - A. Failing to handle contract drift across software versions
   - B. Omitting property-based compliance checks
   - C. Under-specifying public method boundary conditions
   - D. Over-specifying internal details, restricting LLM implementation flexibility

## Answers

- Recap 1: **B**: SDD establishes formal, machine-readable specifications as the single source of truth prior to implementation, decoupling interface contracts from language-specific test scripts. (W05.L2.C1)
- Recap 2: **D**: Machine-readable schemas define public interface signatures and constraints upfront, allowing automated validation of contracts prior to writing implementation code. (W05.L2.C2)
- Quiz 1: **A**: Specifying precise type annotations (`int -> float`) and explicit exception behavior (`raises ValueError`) eliminates ambiguity in method signatures, preventing runtime errors during AI code generation. (W06.L1.C1)
- Quiz 2: **A**: A condition that must always remain true before and after the execution of every public method in a module is a class invariant. (W06.L1.C2)
- Quiz 3: **C**: Executable specifications allow frameworks to automatically synthesize property-based tests that validate general rules across wide ranges of generated inputs. (W06.L1.C3)
- Quiz 4: **B**: Translating module requirements into executable specs requires mapping each business rule to concrete validation schemas, public signatures, and explicit error states for full coverage. (W06.L1.C4)
- Quiz 5: **D**: Over-specifying internal implementation details reduces the flexibility of AI codegen tools; specifications should focus on interface signatures, contracts, and boundary conditions. (W06.L1.C5)
