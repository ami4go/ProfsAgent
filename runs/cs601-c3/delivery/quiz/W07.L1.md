# Review quiz · W07.L1 · Requirements to executable specifications and code generation

## Recap of the previous lecture (5 min)

1. A requirement states: 'A user cannot withdraw an amount exceeding their current balance.' In contract-based design, how is this constraint formally classified for the withdraw method?
   - A. As an implicit parameter signature definition
   - B. As a postcondition that guarantees the balance becomes zero after execution
   - C. As a precondition that must be satisfied by the caller before invoking withdraw
   - D. As a class invariant that applies only when the system shuts down

2. You are defining a pytest-bdd scenario for an e-commerce checkout module. Which action correctly belongs in the step implementation of a 'Given' clause?
   - A. Asserting that the database record status equals COMPLETED
   - B. Initializing a user account with an active balance and populating their shopping cart
   - C. Handling an exception thrown during payment processing
   - D. Calling the checkout() API method on the cart object

3. A payment system requirement specifies that attempting to charge an expired credit card must raise an ExpiredCardException. How should an assertion harness systematically verify this requirement?
   - A. By asserting that the method returns a null transaction ID
   - B. By updating the card expiration date inside the postcondition assertion block
   - C. By verifying that the account balance remains unchanged after calling a non-existent method
   - D. By executing the API call within an assertion harness configured to expect ExpiredCardException

## Review quiz (5 min)

1. Why is it critical to validate specification completeness and parameter boundary conditions before running AI code generation?
   - A. To prevent runtime syntax errors from occurring during executable spec compilation.
   - B. Because missing edge cases allow incorrect or unsafe code implementations to pass the test suite.
   - C. To ensure the LLM automatically generates unit test frameworks during pre-prompting.
   - D. Because executable specifications cannot run unless all public methods are converted into mocks.

2. An AI model generates a candidate implementation that fails two executable test cases with assertion stack traces. In an automated spec-guided feedback loop, what is the correct next action?
   - A. Feed the test error traces back into the LLM context prompt to trigger automated code refinement.
   - B. Delete the failing test cases from the executable specification to force a passing state.
   - C. Regenerate code from scratch with a new framework without supplying the error logs.
   - D. Manually edit the generated source code while disabling failing test assertions.

3. During iterative code generation, your test harness shows 4 out of 5 tests passing, but the final test triggers a runtime assertion failure on null inputs. How should you guide the AI assistant?
   - A. Provide the failed runtime stack trace and null input details to the assistant to iterate until 100% pass.
   - B. Modify the executable specification to stop testing null parameter boundary values.
   - C. Disable runtime assertion checks inside the execution harness to achieve green test results.
   - D. Accept the implementation because an 80% pass rate meets standard deployment criteria.

4. A team suspects AI-generated code has overfitted to the test suite by returning hardcoded values matching test mocks rather than implementing actual business logic. Which technique best detects this issue?
   - A. Running static code linters to check variable naming consistency.
   - B. Increasing the execution timeout threshold in the test runner harness.
   - C. Applying mutation testing to inject code changes and check if test suite failures are triggered.
   - D. Refactoring public methods into private helper methods.

## Answers

- Recap 1: **C**: Preconditions specify the criteria and obligations that must be true prior to invoking a method, such as validating that the requested withdrawal amount does not exceed the balance. (W06.L2.C1)
- Recap 2: **B**: In spec-driven BDD frameworks, 'Given' steps set up the required initial context and state before any action or triggering event occurs. (W06.L2.C2)
- Recap 3: **D**: Translating exception requirements into executable specifications requires wrapping the target method call in an assertion harness that validates the expected exception is raised. (W06.L2.C3)
- Quiz 1: **B**: Incomplete specifications or omitted boundary checks allow incorrect AI-generated code to pass test suites while violating interface contracts. (W07.L1.C1)
- Quiz 2: **A**: Automated feedback loops use error traces and test harness outputs as prompt context for the LLM to iteratively refine code until interface compliance is met. (W07.L1.C2)
- Quiz 3: **A**: Iterative spec-driven generation requires capturing runtime test outputs and feeding stack traces back into the assistant until 100% of specification steps pass. (W07.L1.C3)
- Quiz 4: **C**: Mutation testing introduces small code perturbations; if modified or hardcoded logic still passes tests, it exposes spec overfitting and mock cheating. (W07.L1.C4)
