# Review quiz · W07.L2 · Iterative development and loop engineering

## Recap of the previous lecture (5 min)

1. Why is it critical to validate specification completeness and parameter boundary conditions before running AI code generation?
   - A. To prevent runtime syntax errors from occurring during executable spec compilation.
   - B. Because missing edge cases allow incorrect or unsafe code implementations to pass the test suite.
   - C. To ensure the LLM automatically generates unit test frameworks during pre-prompting.
   - D. Because executable specifications cannot run unless all public methods are converted into mocks.

2. An AI model generates a candidate implementation that fails two executable test cases with assertion stack traces. In an automated spec-guided feedback loop, what is the correct next action?
   - A. Feed the test error traces back into the LLM context prompt to trigger automated code refinement.
   - B. Delete the failing test cases from the executable specification to force a passing state.
   - C. Regenerate code from scratch with a new framework without supplying the error logs.
   - D. Manually edit the generated source code while disabling failing test assertions.

3. During iterative code generation, your test harness shows 4 out of 5 tests passing, but the final test triggers a runtime assertion failure on null inputs. How should you guide the AI assistant?
   - A. Provide the failed runtime stack trace and null input details to the assistant to iterate until 100% pass.
   - B. Modify the executable specification to stop testing null parameter boundary values.
   - C. Disable runtime assertion checks inside the execution harness to achieve green test results.
   - D. Accept the implementation because an 80% pass rate meets standard deployment criteria.

## Review quiz (10 min)

1. In AI-assisted coding, what is the primary function of the generate-test-refactor cycle within iterative loop engineering?
   - A. To replace traditional test-driven development by delegating code review entirely to offline models
   - B. To iteratively generate candidate solutions, run tests to verify correctness, and refine the code based on execution feedback
   - C. To measure hardware resource consumption during model inference
   - D. To produce the complete production codebase in a single prompt execution without feedback

2. In a standard agent execution log schema comprising timestamp, event type, agent identifier, and payload, which field holds the event-specific details necessary to reconstruct the step's operation?
   - A. Timestamp
   - B. Payload
   - C. Agent identifier
   - D. Event type

3. An agent execution log displays the following entry sequence: `[DECISION] Evaluate test failure -> [BRANCH] Select patch strategy -> [CALL] execute_refactor()`. How should `[DECISION]` be categorized in the control-flow taxonomy?
   - A. A repeated deterministic loop iteration
   - B. A target code conditional statement
   - C. A low-level system function invocation
   - D. An agent decision point where the model evaluates context to pick the next step

4. You need to add real-time telemetry to a Python-based coding agent using OpenTelemetry. Which approach correctly captures control-flow steps across agent execution loops?
   - A. Redirecting standard print output to a local text file at the end of execution
   - B. Injecting instrumentation hooks that create structured trace spans around key loop events and function calls
   - C. Configuring the agent to log event data only when an uncaught exception is thrown
   - D. Executing the agent inside a debugger and taking manual heap dumps after every loop

5. While tracing an agent execution log, you observe three consecutive `[TEST_FAIL]` entries accompanied by `[PATCH_APPLIED]` logs, followed by a final `[TEST_PASS]` log. What does this path reveal about the agent's control flow?
   - A. The test framework failed to run due to missing dependencies during the first three attempts
   - B. The agent modified three independent modules simultaneously in parallel threads
   - C. The agent completed three generate-test-refactor loop iterations before achieving a working solution
   - D. The agent experienced a runtime crash and restarted from scratch three times

6. A student instruments a skeleton agent but forgets to add log statements inside the exception-handling branch of the refactoring loop. What issue will occur when verifying log coverage?
   - A. The agent's LLM requests will be rejected by the API endpoint
   - B. The output log will lack control-flow steps whenever an exception occurs, creating missing gaps in the execution trace
   - C. The generated code diffs will automatically revert to their initial state
   - D. The agent will fail to compile in Python

7. Two multi-agent workers generate overlapping code diffs on a repository. Which combination of log fields is required to correlate a specific code diff to the agent action that produced it?
   - A. Agent identifier and precise timestamp aligned with the git commit metadata
   - B. Source file line count and linter severity score
   - C. Model token count and local system memory usage
   - D. Python library version and environment process ID

8. An agent log displays entries like `[INFO] Task started` and `[INFO] Task completed`, but lacks detailed entries for intermediate decision points, test outcomes, or code diffs. Which anti-pattern does this illustrate?
   - A. Timestamp drift
   - B. Excessive log verbosity
   - C. Missing context and inconsistent granularity
   - D. Agent ID collision

## Answers

- Recap 1: **B**: Incomplete specifications or omitted boundary checks allow incorrect AI-generated code to pass test suites while violating interface contracts. (W07.L1.C1)
- Recap 2: **A**: Automated feedback loops use error traces and test harness outputs as prompt context for the LLM to iteratively refine code until interface compliance is met. (W07.L1.C2)
- Recap 3: **A**: Iterative spec-driven generation requires capturing runtime test outputs and feeding stack traces back into the assistant until 100% of specification steps pass. (W07.L1.C3)
- Quiz 1: **B**: The generate-test-refactor cycle continuously improves code quality by emitting candidate code, verifying it against automated tests, and refactoring based on pass/fail signals. (W07.L2.C1)
- Quiz 2: **B**: The payload carries contextual data, arguments, and state outputs needed to analyze what occurred during that specific control-flow step. (W07.L2.C2)
- Quiz 3: **D**: Agent decision points represent high-level reasoning steps where the agent analyzes past execution context to decide subsequent control flow. (W07.L2.C3)
- Quiz 4: **B**: Instrumentation frameworks like OpenTelemetry use structured hooks and spans to emit execution steps in real time, enabling control-flow tracing. (W07.L2.C4)
- Quiz 5: **C**: Repeated test failure and patch entries indicate an iterative refactoring loop where the agent iteratively generates fixes until the test suite passes. (W07.L2.C5)
- Quiz 6: **B**: Missing log statements in specific control-flow branches prevents full control-flow verification because execution steps through that branch remain unrecorded. (W07.L2.C6)
- Quiz 7: **A**: Correlating log entries with code diffs requires matching unique agent IDs and precise execution timestamps against version control commit timestamps. (W07.L2.C7)
- Quiz 8: **C**: Logging only start/end markers without payload context or fine-grained step details is a classic anti-pattern of coarse granularity and missing context, rendering traces uninformative. (W07.L2.C8)
