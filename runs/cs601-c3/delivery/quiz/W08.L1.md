# Review quiz · W08.L1 · Iterative development and loop engineering

## Recap of the previous lecture (5 min)

1. In AI-assisted coding, what is the primary function of the generate-test-refactor cycle within iterative loop engineering?
   - A. To replace traditional test-driven development by delegating code review entirely to offline models
   - B. To iteratively generate candidate solutions, run tests to verify correctness, and refine the code based on execution feedback
   - C. To measure hardware resource consumption during model inference
   - D. To produce the complete production codebase in a single prompt execution without feedback

2. In a standard agent execution log schema comprising timestamp, event type, agent identifier, and payload, which field holds the event-specific details necessary to reconstruct the step's operation?
   - A. Timestamp
   - B. Payload
   - C. Agent identifier
   - D. Event type

3. An agent execution log displays the following entry sequence: `[DECISION] Evaluate test failure -> [BRANCH] Select patch strategy -> [CALL] execute_refactor()`. How should `[DECISION]` be categorized in the control-flow taxonomy?
   - A. A repeated deterministic loop iteration
   - B. A target code conditional statement
   - C. A low-level system function invocation
   - D. An agent decision point where the model evaluates context to pick the next step

## Review quiz (5 min)

1. Why is establishing a standardized log schema and step taxonomy essential before analyzing complex agent execution traces?
   - A. It increases the LLM token generation speed during iterative loops.
   - B. It provides a shared vocabulary and consistent structure to correctly classify control-flow steps.
   - C. It automatically refactors source code whenever an execution error is logged.
   - D. It guarantees that the agent will never enter an infinite execution loop.

2. When tracing a log file containing concurrent agent executions, how can you correctly group interleaved execution steps into their respective logical loops?
   - A. Sort all log entries purely by timestamp and assign them to sequential loops.
   - B. Filter and group log entries using their correlation IDs assigned to each execution context.
   - C. Combine all concurrent steps into a single main execution sequence.
   - D. Ignore parallel steps and only trace log entries containing syntax errors.

3. While analyzing a production coding agent log, you observe that the agent repeatedly re-runs tests after a failure without applying any code edits. Which bottleneck or instrumentation gap does this reveal?
   - A. The log analyzer failed to assign parallel loop correlation IDs.
   - B. The agent needs higher network bandwidth to execute tests faster.
   - C. The agent's log schema lacks compression for long trace outputs.
   - D. The generate-test-refactor loop is stuck because failure signals are not triggering code modifications.

4. In a trace report for an iterative development task, what is the primary objective of linking logged control-flow steps to specific code artifacts?
   - A. To prevent the coding agent from editing files outside the root directory.
   - B. To establish clear traceability between log events, test outputs, and exact code changes made across iterations.
   - C. To eliminate the need for version control during agentic development.
   - D. To measure the network API latency of each model invocation.

## Answers

- Recap 1: **B**: The generate-test-refactor cycle continuously improves code quality by emitting candidate code, verifying it against automated tests, and refactoring based on pass/fail signals. (W07.L2.C1)
- Recap 2: **B**: The payload carries contextual data, arguments, and state outputs needed to analyze what occurred during that specific control-flow step. (W07.L2.C2)
- Recap 3: **D**: Agent decision points represent high-level reasoning steps where the agent analyzes past execution context to decide subsequent control flow. (W07.L2.C3)
- Quiz 1: **B**: A standardized log schema and step taxonomy establish a common structure and vocabulary, allowing developers to accurately identify and classify control-flow events across execution logs. (W08.L1.C1)
- Quiz 2: **B**: Correlation IDs tag entries from the same logical execution context, allowing interleaved log steps from parallel or nested loops to be cleanly separated and traced. (W08.L1.C2)
- Quiz 3: **D**: A repeated test loop without code edits indicates a broken generate-test-refactor cycle where failure states do not properly trigger or log refactoring actions. (W08.L1.C3)
- Quiz 4: **B**: Linking log control-flow steps to code artifacts establishes concrete auditability, showing exactly which code changes and test results correspond to each step in the loop. (W08.L1.C4)
