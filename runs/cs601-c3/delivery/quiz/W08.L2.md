# Review quiz · W08.L2 · Iterative development logs and software factory outputs

## Recap of the previous lecture (5 min)

1. Why is establishing a standardized log schema and step taxonomy essential before analyzing complex agent execution traces?
   - A. It increases the LLM token generation speed during iterative loops.
   - B. It provides a shared vocabulary and consistent structure to correctly classify control-flow steps.
   - C. It automatically refactors source code whenever an execution error is logged.
   - D. It guarantees that the agent will never enter an infinite execution loop.

2. When tracing a log file containing concurrent agent executions, how can you correctly group interleaved execution steps into their respective logical loops?
   - A. Sort all log entries purely by timestamp and assign them to sequential loops.
   - B. Filter and group log entries using their correlation IDs assigned to each execution context.
   - C. Combine all concurrent steps into a single main execution sequence.
   - D. Ignore parallel steps and only trace log entries containing syntax errors.

3. While analyzing a production coding agent log, you observe that the agent repeatedly re-runs tests after a failure without applying any code edits. Which bottleneck or instrumentation gap does this reveal?
   - A. The log analyzer failed to assign parallel loop correlation IDs.
   - B. The agent needs higher network bandwidth to execute tests faster.
   - C. The agent's log schema lacks compression for long trace outputs.
   - D. The generate-test-refactor loop is stuck because failure signals are not triggering code modifications.

## Review quiz (10 min)

1. Which software factory artifact should you inspect to verify the complete list of declared dependencies and output binary schemas for a specific build?
   - A. Test execution summary
   - B. Tool invocation logs
   - C. Commit metadata
   - D. Artifact manifest

2. A test suite passes on the first run, fails on the second run without code changes, and passes on the third. Which seeded defect category does this signature indicate?
   - A. Flaky test
   - B. Missing dependency
   - C. Resource leak
   - D. Configuration drift

3. You need to extract failure messages specifically from JSON-formatted factory build logs. Which command line approach is most appropriate?
   - A. sed -n '/ERROR/p' build.log
   - B. grep -i "error" build.log
   - C. tail -n 50 build.log
   - D. jq '.steps[] | select(.status=="failed") | .error' build.log

4. A build fails with `ClassNotFoundException: com.example.Utils`. The artifact manifest lists the library under `runtime_dependencies`, but it is missing from the compile classpath log. What is the root cause?
   - A. Missing compile-time dependency configuration
   - B. Resource leak during compilation
   - C. Test execution flakiness
   - D. Configuration drift on the build runner

5. In a set of development logs, system memory usage increases monotonically across 20 consecutive test runs until an `OutOfMemoryError` occurs. What is the proper fix proposal?
   - A. Lower the log verbosity level to conserve memory
   - B. Explicitly release unclosed file and database handles in test teardown hooks
   - C. Increase physical RAM allocated to the build agent
   - D. Add automated retries for tests failing with out-of-memory errors

6. Why might a timing-sensitive defect manifest as a hard stack trace under high log verbosity but as a non-deterministic timeout failure under low log verbosity?
   - A. Higher verbosity changes the schema of artifact manifests
   - B. Low verbosity causes automatic configuration drift remediation
   - C. Additional logging I/O alters thread execution timing and race condition windows
   - D. Build artifacts strip memory allocation metadata when verbosity drops

7. A software factory build succeeds on staging build nodes but fails on production release nodes due to missing OS environment variables. Which strategy best prevents this configuration drift defect?
   - A. Increase log verbosity on release nodes to capture environment variables
   - B. Enforce immutable containerized build environments defined in version-controlled configuration
   - C. Manually update release node environment variables before every run
   - D. Implement automatic retry steps when environment errors occur

8. A proposed defect fix catches all broad exceptions silently inside a shared data module to prevent build pipeline failures. How should this proposal be evaluated?
   - A. Reject it due to high regression risk and poor testability from masking root errors
   - B. Reject it because data module fixes must always be applied via artifact manifests
   - C. Accept it because it successfully eliminates build step failures
   - D. Accept it provisionally after adding high-verbosity debug logs

## Answers

- Recap 1: **B**: A standardized log schema and step taxonomy establish a common structure and vocabulary, allowing developers to accurately identify and classify control-flow events across execution logs. (W08.L1.C1)
- Recap 2: **B**: Correlation IDs tag entries from the same logical execution context, allowing interleaved log steps from parallel or nested loops to be cleanly separated and traced. (W08.L1.C2)
- Recap 3: **D**: A repeated test loop without code edits indicates a broken generate-test-refactor cycle where failure states do not properly trigger or log refactoring actions. (W08.L1.C3)
- Quiz 1: **D**: The artifact manifest defines the output schemas and declared dependencies of built artifacts, whereas logs capture runtime execution details. (W08.L2.C1)
- Quiz 2: **A**: Non-deterministic test failures occurring under identical code conditions are the characteristic signature of a flaky test defect. (W08.L2.C2)
- Quiz 3: **D**: Using jq allows structural field projection and conditional filtering on structured JSON logs, which line-oriented tools like grep cannot reliably do. (W08.L2.C3)
- Quiz 4: **A**: The error trace shows a missing dependency required at compile time because it was incorrectly categorized only as a runtime dependency. (W08.L2.C4)
- Quiz 5: **B**: Monotonic memory growth leading to out-of-memory errors across runs indicates a resource leak, requiring explicit cleanup of unclosed handles in code. (W08.L2.C5)
- Quiz 6: **C**: Log verbosity affects system execution speed and I/O latency, which alters how non-deterministic timing defects manifest across iterations. (W08.L2.C6)
- Quiz 7: **B**: Configuration drift between factory nodes is prevented by defining immutable container environments within version-controlled infrastructure code. (W08.L2.C7)
- Quiz 8: **A**: Silent exception handling hides failure conditions rather than fixing the root cause, creating high regression risks and making future testing unreliable. (W08.L2.C8)
