# Review quiz · W10.L1 · Testing and validation in iterative development

## Recap of the previous lecture (5 min)

1. Why is consistent formatting of metadata (such as event types, timestamps, and error codes) critical in agent execution traces?
   - A. It automatically fixes failed tool calls without human intervention.
   - B. It allows automated tools to reliably parse and map execution steps across iterative loops.
   - C. It compresses the log file size to reduce disk overhead.
   - D. It prevents the agent from making invalid syntax calls during execution.

2. An execution trace shows an agent calling a file-write tool 10 times in a row, each returning an error code indicating the destination directory does not exist. What is the root cause shown by this trace?
   - A. The file system permissions were revoked mid-execution.
   - B. The agent is misusing the tool by supplying an invalid path and failing to handle the returned error.
   - C. The system experienced an intermittent network timeout across iterations.
   - D. The trace logger dropped event records between iterations.

## Review quiz (10 min)

1. You need to quickly count how many times HTTP 500 error codes appear in a 2000-line JSON execution trace file. Which command-line approach is most appropriate?
   - A. Use awk to replace all timestamps with text strings before scanning with grep.
   - B. Pass the raw trace into an LLM prompt to estimate error frequencies without parsing.
   - C. Use jq to parse the JSON logs, filter by the error code field, and count occurrences.
   - D. Manually scroll through the raw text file in an editor to count 500 error strings.

2. An engineer suspects an agent failed due to a missing permission in iteration 3, but modifies the source code without inspecting the log context. Which step of the systematic trace analysis workflow was skipped?
   - A. Running initial setup scripts before trace collection.
   - B. Searching for signature patterns and collecting log evidence to validate the hypothesis.
   - C. Formulating initial failure hypotheses.
   - D. Segmenting the trace by iteration index.

3. During log analysis, an agent repeatedly executes the exact same shell command without advancing state across multiple log segments. What failure type does this represent, and what log evidence confirms it?
   - A. A version mismatch, confirmed by dynamic library load warnings.
   - B. A permission error, confirmed by EACCES denial flags in step outputs.
   - C. A hardware crash, confirmed by sudden termination of process IDs.
   - D. A logic loop, confirmed by repeating sequential log lines with identical step actions.

4. When preparing a trace analysis report on a fresh 1500-line log file for peer review, which set of details makes the report verifiable?
   - A. A general summary of agent behavior without line numbers or error codes.
   - B. The agent's initial prompt text combined with total execution time.
   - C. An unannotated copy of the entire trace file without identified root causes.
   - D. Identified failure causes paired with explicit log line numbers and error codes.

5. A team needs to evaluate trace analysis strategies for high accuracy and low false-positive rates regarding exact error codes. How should they compare scripted querying with LLM-assisted summarisation?
   - A. Manual inspection is faster and less prone to human error than both scripted queries and LLM summarisation.
   - B. Scripted querying should be avoided because it cannot count occurrence frequencies in large files.
   - C. LLM summarisation guarantees zero false positives when extracting specific error codes compared to scripted tools.
   - D. Scripted querying provides deterministic accuracy for specific codes, whereas LLM summarisation can introduce false positives.

6. You have identified a root cause from a trace log and are structuring a failure report for developers. Which approach ensures the findings are validated and actionable?
   - A. Request developers to re-run the trace manually without providing cited line numbers.
   - B. Rely entirely on stakeholder opinions rather than log verification.
   - C. Validate the cause with a reproducing unit test and link actionable fixes to specific log evidence.
   - D. Provide high-level developer advice without linking back to specific log lines.

## Answers

- Recap 1: **B**: Consistent trace metadata formatting allows automated parsers to reliably extract step outputs, map iteration loops, and spot execution failures. (W09.L2.C1)
- Recap 2: **B**: Repeated tool calls with bad arguments yielding the same error code demonstrate tool misuse, where the agent repeatedly inputs an invalid path without interpreting the error return code. (W09.L2.C2)
- Quiz 1: **C**: Tools like jq allow structured parsing of JSON traces to accurately filter specific fields and count error codes without manual searching. (W10.L1.C1)
- Quiz 2: **B**: The workflow requires searching for signature patterns and collecting concrete log lines to validate failure hypotheses before altering the code context. (W10.L1.C2)
- Quiz 3: **D**: Repeatedly executing identical commands without state progression indicates a logic loop, evidenced by repeating sequences in execution log traces. (W10.L1.C3)
- Quiz 4: **D**: Peer review requires concrete evidence, including explicit log line numbers and error codes, to support each identified failure cause. (W10.L1.C4)
- Quiz 5: **D**: Scripted querying (e.g., grep, jq) offers precise code extraction without false positives, whereas LLM-assisted summarisation carries a risk of hallucinations despite being fast for high-level summaries. (W10.L1.C5)
- Quiz 6: **C**: Actionable reporting requires direct traceability back to log evidence combined with concrete validation methods such as reproducing unit tests. (W10.L1.C6)
