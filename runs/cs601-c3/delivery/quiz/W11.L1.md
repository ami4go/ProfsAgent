# Review quiz · W11.L1 · Automated testing and evaluation mechanisms

## Review quiz (0 min)

1. You are auditing an AI-native recommendation API that currently relies only on static unit tests and offline Precision@K metrics. Your gap analysis reveals that the system frequently fails when real users request rare categories. Which improvement best addresses this evaluation gap?
   - A. Increase code coverage of the API route handlers to 100%.
   - B. Integrate behavioral test suites using edge-case inputs alongside online slice-based evaluation metrics.
   - C. Measure latency using load testing tools without changing model evaluation metrics.
   - D. Switch the recommendation algorithm database from PostgreSQL to Redis.

2. An engineering team is selecting an automated testing mechanism for a real-time recommendation system. They need to evaluate output quality under live data distribution shifts without disrupting user experience. Which framework setup is most appropriate?
   - A. Stress testing the database under peak load.
   - B. Manual code reviews of the model prompt and architecture.
   - C. Shadow deployment combined with automated divergence and drift metrics.
   - D. Offline unit testing using static mock inputs.

3. A evaluation framework for a recommendation API measures accuracy (Recall@K) and API latency. However, users complain that the recommendations feel repetitive and predictable. Which metric should be added to the comparative evaluation framework to fix this assessment gap?
   - A. Response Time Percentile (P99)
   - B. Mean Time To Recovery (MTTR)
   - C. Intra-List Diversity (ILD) or Novelty Score
   - D. Cyclomatic Complexity of the API pipeline

4. You are reviewing an AI-native recommendation API's evaluation pipeline that lacks robust failure mode detection. Propose one automated testing mechanism and one metric to evaluate how gracefully the system handles out-of-domain inputs.

## Answers

- Quiz 1: **B**: Addressing coverage gaps in AI services requires behavioral testing targeted at edge cases and slice-based metrics to evaluate sub-population performance beyond aggregate precision. (W11.L1.C1)
- Quiz 2: **C**: Shadow deployment allows real-time evaluation against live production traffic using drift/divergence metrics without impacting actual end users. (W11.L1.C1)
- Quiz 3: **C**: Intra-List Diversity directly measures the variety of recommended items within a list, resolving the gap where accuracy metrics favor repeated popular items. (W11.L1.C1)
- Quiz 4: **Implement adversarial perturbational testing (or behavioral testing) with synthetic out-of-domain inputs, and measure Fallback/Refusal Rate or Out-of-Distribution (OOD) Detection Accuracy.**: Adversarial or behavioral testing generates non-standard inputs to test resilience, while Fallback or OOD detection metrics measure whether the system safely defaults to non-hallucinated responses. (W11.L1.C1)
