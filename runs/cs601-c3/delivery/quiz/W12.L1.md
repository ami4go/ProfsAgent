# Review quiz · W12.L1 · Reliable and safe trustworthy software architectures

## Recap of the previous lecture (5 min)

1. In an automated AI-native software factory pipeline, what is the primary role of the model validation stage before deployment?
   - A. To convert raw unstructured data into standardized formats for ingestion
   - B. To re-train base models using real-time production feedback
   - C. To evaluate model performance and safety metrics against defined thresholds before release
   - D. To run stress tests on infrastructure hardware to check server latency under load

2. A team notices their deployed ML system's accuracy degrades over time despite passing all code unit tests and initial validation. Which automated testing stage should be added to catch this issue early?
   - A. Continuous data drift detection stage
   - B. Unit testing of feature engineering functions
   - C. Code syntax linting stage
   - D. Integration testing of data ingestion APIs

3. A team needs to satisfy a strict reproducibility requirement for a safety-critical AI system. How does this requirement alter pipeline test design compared to a system focused primarily on execution latency?
   - A. Reproducibility requires replacing integration tests with unit tests across all stages.
   - B. Reproducibility is tested exclusively in post-deployment monitoring, whereas latency is tested pre-training.
   - C. Reproducibility requires adding automated checks for data versioning, fixed seeds, and pipeline environment hashing.
   - D. Reproducibility mandates disabling automated data drift detection to keep training fixed.

## Review quiz (10 min)

1. Why is it necessary to map automated testing pipeline stages back to explicit reliability requirements before evaluating a pipeline?
   - A. It eliminates the need for manual code reviews in multi-component software factories.
   - B. It replaces the need for defining Service-Level Objectives across AI services.
   - C. It ensures every test stage directly validates at least one target reliability objective rather than testing arbitrarily.
   - D. It automatically guarantees zero downstream production failures regardless of test quality.

2. An AI-native application relies on three cascading microservices. If upstream Service A fails, it triggers downstream failures in Services B and C. Which mechanism should be incorporated into the reliability specification to mitigate this?
   - A. Increase the error budget of Service C to absorb model drift.
   - B. Increase the test coverage threshold of Service B's unit tests to 100%.
   - C. Replace all automated integration tests with manual end-to-end checks.
   - D. Define a cascade failure policy such as circuit breaking or fallback responses between services.

3. An engineering team instrumented their production AI pipeline with real-time dynamic data profiling, but observed a significant increase in pipeline execution cost and latency. What trade-off is demonstrated in this case study?
   - A. Deterministic output generation vs. stochastic model training speed.
   - B. High test coverage vs. zero security vulnerability detection.
   - C. Deep operational observability vs. resource consumption and execution latency.
   - D. Automated integration testing vs. manual test writing effort.

4. In assessing a pipeline design decision to run heavy end-to-end model validation on every git commit, an evaluator finds developer delivery speed has dropped significantly. How should this design decision be re-justified against reliability requirements?
   - A. Move heavy model validation to a pre-release or nightly trigger while keeping fast unit tests on every commit.
   - B. Lower the accuracy thresholds of the heavy validation tests so they finish running faster.
   - C. Retain the heavy test stage on every commit to maintain maximum theoretical test rigor regardless of velocity cost.
   - D. Remove all end-to-end model validation entirely from the deployment pipeline.

5. During peer review of a multi-component AI pipeline, Group A notices that Group B justified skipping integration testing between the parser and recommender services because both pass unit tests. Why is this justification inadequate?
   - A. Peer review guidelines require every single component to have identical deployment scripts.
   - B. Skipping integration testing violates the system's error budget tracking rules.
   - C. Unit tests run slower than integration tests in multi-component pipelines.
   - D. Isolated unit tests cannot verify cross-component contract failures, schema mismatches, or cascading errors between AI services.

6. A team needs to lower deployment latency for critical security hotfixes in an AI service. When comparing exhaustive model regression testing against high deployment speed, which strategy best manages this trade-off for urgent fixes?
   - A. Bypass all pipeline checks and deploy directly to production without testing.
   - B. Double the error budget so that broken deployments do not count against service level objectives.
   - C. Run full synthetic model evaluation suites before deploying any hotfix.
   - D. Execute a targeted subset of regression tests for affected components, deferring full model suites to post-deployment staging.

## Answers

- Recap 1: **C**: The model validation stage ensures that a newly trained model meets accuracy, fairness, and safety thresholds before it is automatically promoted to deployment. (W11.L3.C1)
- Recap 2: **A**: Continuous data drift detection monitors live input data distributions against training distributions, identifying shifts that degrade model accuracy in production. (W11.L3.C2)
- Recap 3: **C**: Mapping reproducibility to test design requires validating deterministic execution (seeds, data split versions, environment hashing), whereas latency requirements focus on timing and throughput checks under load. (W11.L3.C3)
- Quiz 1: **C**: Mapping pipeline stages to explicit reliability requirements ensures that test design decisions directly serve specific system reliability objectives rather than performing redundant or unaligned testing. (W12.L1.C1)
- Quiz 2: **D**: Formalizing a cascade failure policy (e.g., using circuit breakers or fallbacks) prevents an upstream failure in a multi-component AI system from causing dependent downstream services to fail. (W12.L1.C2)
- Quiz 3: **C**: Instrumenting deep observability in production pipelines often improves visibility into reliability failures, but comes at the expense of higher resource utilization and execution delays. (W12.L1.C3)
- Quiz 4: **A**: Aligning pipeline design decisions with reliability goals requires balancing feedback speed and rigor; tiering expensive validation tests to pre-release triggers preserves developer feedback loops while meeting reliability requirements. (W12.L1.C4)
- Quiz 5: **D**: In multi-component AI factories, passing unit tests in isolation fails to validate inter-service interactions, data drift handling, and contract compatibility, making integration testing necessary for reliability justification. (W12.L1.C5)
- Quiz 6: **D**: To balance deployment speed against testing depth during urgent hotfixes, teams run targeted test suites focused on impacted components while scheduling full, resource-intensive validation suites post-deployment. (W12.L1.C6)
