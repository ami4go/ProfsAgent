# Review quiz · W13.L1 · Deployment and reliability metric evaluation

## Review quiz (0 min)

1. During a deployment, an engineer observes an immediate spike in error rates after shifting 5% of traffic to a new version. How does this canary metric pattern alter the rollback decision compared to a blue-green switch?
   - A. Canary limits the failure impact to 5% of users, enabling a low-risk rollback before full traffic cutover.
   - B. Blue-green allows rolling back only the failing 5% of pods while leaving the rest running.
   - C. Blue-green metric patterns isolate failures to individual canary pods, avoiding environment-wide rollbacks.
   - D. Canary requires draining all active user sessions across the entire cluster before rolling back.

2. A monitoring dashboard shows System X suffering an immediate error spike across 100% of requests upon deployment, while System Y shows errors localized to a small percentage of requests. What deployment strategies do these metric patterns indicate?
   - A. System X used a canary deployment; System Y used a blue-green deployment.
   - B. Both systems used canary deployments, but System X failed its traffic split configuration.
   - C. Both systems used blue-green deployments, but System Y triggered an automated rollback.
   - D. System X used a blue-green deployment; System Y used a canary deployment.

3. During a live canary rollout, 10% of user traffic is shifted to the canary release. Monitoring in Grafana reveals that the canary's error rate exhausts 80% of the remaining monthly error budget in 10 minutes. What is the correct go/no-go decision and action?
   - A. Issue a 'No-Go' decision, immediately abort/rollback the canary rollout, and document metrics for a post-mortem.
   - B. Issue a 'Go' decision and scale up canary traffic to see if error rates normalize under load.
   - C. Keep traffic at 10% indefinitely while increasing the error budget ceiling in Grafana.
   - D. Issue a 'Go' decision but disable error monitoring to prevent further budget consumption.

4. Why is documenting error budget depletion during a canary evaluation crucial when conducting a post-mortem after a No-Go decision?

## Answers

- Quiz 1: **A**: Canary deployments expose only a small fraction of traffic to the update, allowing engineers to make an early rollback decision while limiting the blast radius of potential failures. (W13.L1.C1)
- Quiz 2: **D**: Blue-green deployments perform an instant, full traffic cutover leading to system-wide metric changes, whereas canary deployments split traffic incrementally, localizing initial metric changes. (W13.L1.C1)
- Quiz 3: **A**: When canary metrics rapidly consume the error budget, the correct evaluation outcome is a 'No-Go' decision to roll back immediately and preserve system reliability, followed by post-mortem analysis. (W13.L1.C2)
- Quiz 4: **It provides metric evidence showing how rapidly reliability targets were breached, helping teams refine automated rollback thresholds and prevent similar failures in future rollouts.**: Documenting metric patterns and error budget burn during a failed canary deployment provides historical context for post-mortems, helping teams calibrate future go/no-go criteria. (W13.L1.C2)
