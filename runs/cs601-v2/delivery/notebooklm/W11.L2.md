## 2 · Course context (paste as a text source)

```text
COURSE: Software Development using AI (IIIT-Delhi, level 3xx, 3/4-year B.Tech students)
LECTURE: W11.L2 · week 11 · Pipeline evaluation mechanisms and metrics (105 minutes)

LEARNING OUTCOMES (what students must be able to do):
- Compare automated testing mechanisms and evaluation metrics for AI-native software architectures.

STUDENTS ALREADY KNOW:
- Automated testing and evaluation mechanisms (week 10)

THIS LECTURE, PART BY PART:
1. AI-Native Testing Landscape Overview (15 min, concept)
   Teaches: Students will identify the unique challenges of testing AI-native systems, including nondeterminism, data drift, and model versioning. They will distinguish between model-centric and system-centric testing concerns.
   Key terms: AI-native, nondeterminism, data drift, model versioning, testing challenges
2. Unit Testing ML Model Components (15 min, mechanism)
   Teaches: Students will describe unit-level testing mechanisms such as property-based testing, metamorphic testing, and test oracle construction for individual model functions. They will explain how these mechanisms detect logic errors in preprocessing, inference, and postprocessing.
   Key terms: property-based testing, metamorphic testing, test oracle, preprocessing, inference
3. Integration Testing of ML Pipelines (15 min, mechanism)
   Teaches: Students will outline integration testing strategies for end-to-end ML pipelines, including contract testing, schema validation, and pipeline replay. They will compare static vs dynamic pipeline validation approaches.
   Key terms: contract testing, schema validation, pipeline replay, static validation, dynamic validation
4. Model Performance Evaluation Metrics (15 min, concept)
   Teaches: Students will define key model-centric metrics such as accuracy, F1, AUC, calibration error, and perplexity, and explain when each is appropriate. They will interpret metric trade-offs for classification, generation, and ranking tasks.
   Key terms: accuracy, F1, AUC, calibration error, perplexity, metric trade-offs
5. System-Level Quality Metrics (15 min, concept)
   Teaches: Students will describe system-level metrics including latency, throughput, memory footprint, robustness to adversarial inputs, and data freshness. They will relate these metrics to SLA requirements in production AI services.
   Key terms: latency, throughput, memory footprint, robustness, data freshness, SLA
6. Mapping Mechanisms to Metrics (15 min, comparison)
   Teaches: Students will apply a comparative framework that links each testing mechanism to the metrics it informs, highlighting coverage gaps. They will evaluate which combination of mechanisms yields comprehensive metric coverage for a given architecture.
   Key terms: comparative framework, coverage gaps, mechanism-metric mapping, comprehensive coverage, architecture
7. Case Study: RAG Pipeline Evaluation (15 min, case study)
   Teaches: Students will walk through a retrieval-augmented generation pipeline, applying unit, integration, and system tests, and compute model and system metrics. They will critique the evaluation plan and suggest improvements.
   Key terms: RAG, retrieval-augmented generation, unit test, integration test, system metrics, critique
```
